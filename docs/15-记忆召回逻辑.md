# 15-记忆召回逻辑

> 参考 MoRanJiangHu（墨色江湖：无尽武林）的实证链路整理，可落地到本卡/工作台的通用记忆召回设计。
> 核心结论：**召回库独立存储；召回 = 一次独立 API 调用；召回结果注入上下文层级（system 段 / 最新用户输入），并作为世界书关键词匹配语料参与命中；召回激活时禁用常规记忆层防重复。**

---

## 一、目标

- 对话进行到一定回合后，每回合（或命中角色提及时）自动从"剧情记忆库"中召回与当前输入最相关的历史剧情。
- 召回结果以结构化标签形式进入上下文，保证模型"记得"关键前因、承诺、旧账、未结事项。
- 与世界书职责分离：世界书管"设定/规则"，记忆召回管"剧情史"。

## 二、总体链路（一回合）

```
用户发送
  ├─ 1. 提取已有标签：/<剧情回忆>([\s\S]*?)<\/剧情回忆>/g → recallTag，剩余为 cleanInput
  ├─ 2. 触发判定：开关开启 && 回忆档案条数 ≥ 门槛 && 无已有标签 && 接口可用
  ├─ 3. 本地预筛：检索词切分 → 相关度打分 → topK + 近因保留
  ├─ 4. 独立 API 召回：COT 提示词 + 回忆库语料 → 模型输出 强/弱回忆 序号
  │      └─ 失败/无结果 → 本地回退结果
  ├─ 5. 构建 recallTag：强回忆=原文，弱回忆=概括
  ├─ 6. 确认/静默：非静默先取消发送，弹窗确认后回填输入，再发送
  ├─ 7. 注入：
  │      A. 上下文：非酒馆 → 拼进「即时剧情回顾」system 段；酒馆 → 拼进最新用户输入
  │      B. 世界书：recallTag 加入世界书关键词匹配语料（不直接注入）
  │      C. 禁用常规 短/中/长期 记忆段，由 recallTag 替代
  └─ 8. 回合收尾：写即时记忆 + 回忆档案 → 超限滑动 → 阈值触发压缩
```

## 三、记忆库（召回库）设计

独立于世界书存储，与世界书完全分离。

```ts
interface 记忆系统 {
  回忆档案: 回忆条目[];   // 每回合一条，召回主库
  即时记忆: string[];     // 近期回合逐条原文（滑动窗口）
  短期记忆: string[];     // 短期摘要
  中期记忆: string[];     // 中期摘要
  长期记忆: string[];     // 长期摘要
}

interface 回忆条目 {
  名称: string;      // 【回忆001】
  概括: string;      // 对应短期摘要
  原文: string;      // 对应即时记忆（时间+玩家输入+AI输出）
  回合: number;      // 顺序号
  记录时间: string;  // 游戏内时间
  时间戳: string;
}
```

写入时机：每次主剧情响应完成后写入一条（见第九节）。

## 四、触发条件

```ts
function 应触发召回(input, mem, config): boolean {
  const 已有标签 = /<剧情回忆>/.test(input);
  const 回合足够 = mem.回忆档案.length + 1 >= config.最早触发回合; // 默认 10
  const 开关 = config.剧情回忆独立模型开关;
  const 接口可用 = getRecallApi() != null;
  return 开关 && 回合足够 && !已有标签 && 接口可用;
}
```

可选增强（本卡如需"按角色提及触发"）：

// 在本地预筛前先做角色提及检测：
const 提及角色 = 提取角色名列表(input);        // 用角色名/别名表匹配
if (提及角色.length > 0) {

## 五、本地预筛（低成本第一道）

```ts
function 预筛候选(playerInput, mem, fullN, topK=24, recentReserve=6) {
  const archives = sort(mem.回忆档案, 回合 asc);
  const fullStart = max(0, archives.length - fullN);   // 最近 fullN 条给原文
  const terms = 提取检索词(playerInput);                // ASCII词 + 中文二元/三元切块

  return archives.map((item, idx) => ({
    ...item,
    是否完整原文: idx >= fullStart,
    相关度: 打分(playerInput, terms, item, idx, archives.length),
  }))
  .取topK高分()
  .合并最近recentReserve条()   // 近因保底
  .去重保序();
}

function 打分(query, terms, item, idx, total): number {
  let score = 0;
  if (query && item.searchable.includes(query)) score += 12;   // 全文命中
  terms.forEach(t => {
    if (item.searchable.includes(t)) score += t.length>=4 ? 5 : t.length===3 ? 3 : 1.5;
  });
  score += ((idx + 1) / total) * 3;                            // 近因加成
  return score;
}
```

## 六、独立 API 召回（核心）

一次独立于主剧情的模型请求，可用独立 Base URL / Key / 模型：

```
system:  <COT 提示词> + <输出格式>
user:    【玩家输入】\n{input}\n\n【回忆库】\n{语料}
（可选）user: 【额外要求提示词】…      （来自游戏设置.额外提示词）
（可选）assistant: COT伪装历史消息
temperature: 0.2
```

- **语料构建**：`【本地预筛可能相关】\n候选名列表` + 每条回忆——最近 fullN 条给原文，更早只给概括；预筛命中条目标注"本地预筛：可能相关"。
- **COT 要点**：
  - 强回忆 = 高度相关且需保留原文细节；弱回忆 = 相关但概括即可。
  - 优先匹配：人物、地点、目标、未结事项、冲突对象、承诺、伤势、物品、判定结果。
  - 同一事件多条近似回忆 → 选更近、更完整、更直接承接的。
  - 强回忆不设 1~2 上限；连续事件链 / 同一对象多轮互动 / 多段冲突串联可 3~6 条。
  - 不要为精简漏掉仍在生效的前因、承诺、旧账、未结事项、上一轮明确结论。
- **输出格式**（严格两行）：

```
强回忆：【回忆005】|【回忆012】
弱回忆：【回忆007】
// 无则写：强回忆:无
```

- **解析**：找 `强回忆:` / `弱回忆:` 行 → 提取 `【回忆\d+】` 序号 → 强去重、弱剔除已入强。
- **回退链**：
  1. 模型输出无强无弱 → 用本地回退结果；
  2. 任何异常（超时/解析失败）→ 本地回退结果。
- **本地回退算法**：候选按相关度降序；首条必入强；其余按 topScore 比例阈值过滤（idx<3 需 ≥60%，idx<6 需 ≥72%，之后需 ≥max(8, 82%)）；强最多 6、弱最多 6。

## 七、标签构建与确认

```ts
function 构建标签(parsed, mem): string {
  return [
    '强回忆：',
    ...parsed.strongIds.map(id => `${id}：\n${mem[id].原文 || '（无原文）'}`),   // 强=原文
    '',
    '弱回忆：',
    ...parsed.weakIds.map(id => `${id}：\n${mem[id].概括 || '（无概括）'}`),     // 弱=概括
  ].join('\n');
}
```

确认策略（可选）：
- 非静默：召回后**取消本次发送**，弹窗预览（强/弱回忆），用户确认 → 标签回填输入框（显示"已回填（待发送）"）→ 用户再点发送。
- 静默：直接采用，不打断。

## 八、注入策略（层级归属）

| 通道 | 去向 | 层级 |
|---|---|---|
| A. recallTag 本体（非酒馆） | 拼进「即时剧情回顾」段（`【剧情回忆】\n{tag}`），作为 system 消息注入 | **上下文** |
| B. recallTag 本体（酒馆） | `用户输入 + \n<剧情回忆>\n{tag}\n</剧情回忆>`，作为最新用户输入 | **上下文** |
| C. recallTag 副本 | 加入世界书 `extraTexts` → 只进关键词匹配语料（命中判定），**不直接注入** | 世界书（间接） |
| D. 防重复 | 召回激活时 `禁用短期记忆` / `禁用中期长期记忆`，对应 system 记忆段清空 | — |

要点：**召回内容永远不进世界书条目文本**；世界书只借 recallTag 提升相关条目命中率（比如回忆提到某地点/人物，触发对应世界书条目）。

## 九、回合收尾维护（记忆写入 + 压缩）

```ts
function 回合收尾(prev, gameTime, playerInput, aiResponse, config) {
  const 即时条目 = `【${gameTime}】\n玩家输入：${playerInput}\nAI输出：\n${logsText}`;
  const 短期条目 = aiResponse.shortTerm || logs前180字;

  next.即时记忆.push(即时条目 + '\n<<SHORT_TERM_SYNC>>\n' + 短期条目);
  next.回忆档案.push({ 名称: 【回忆${回合}】, 概括: 短期条目, 原文: 即时条目, 回合, 时间 });

  // 滑动窗口：即时记忆 > N(默认10) → shift 最旧，其短期摘要并入短期记忆
  while (next.即时记忆.length > config.即时消息上传条数N) {
    const old = next.即时记忆.shift();
    next.短期记忆.push(拆分(old).短期摘要);
  }
  return next;
}
```

自动压缩触发（写入后检查）：
- `短期记忆 > 短期记忆阈值(默认30)` → 生成「短期→中期」任务；
- `中期记忆 > 中期记忆阈值(默认50)` → 生成「中期→长期」任务。
- 压缩流程：弹窗提醒 → 用户确认 → **独立记忆总结 API** → 草稿审阅 → 确认 → splice 源层 + push 时间戳化摘要。

## 十、参数配置表

| 参数 | 默认 | 说明 |
|---|---|---|
| 剧情回忆独立模型开关 | off | 总开关；可独立配置模型/BaseURL/Key |
| 剧情回忆静默确认 | off | on=召回结果直接采用，不弹确认 |
| 剧情回忆完整原文条数N | 20 | 语料中最近 N 条给原文，更早只给概括 |
| 剧情回忆最早触发回合 | 10 | 回忆档案 ≥N 条才触发 |
| 即时消息上传条数N | 10 | 即时记忆滑动窗口 |
| 短期记忆阈值 | 30 | 触发短期→中期压缩 |
| 中期记忆阈值 | 50 | 触发中期→长期压缩 |
| NPC记忆总结阈值 | 20 | 单 NPC 记忆条数达阈值后聚合 |

## 十一、伪代码（发送主流程）

```ts
async function onSend(input, state, config) {
  const { cleanInput, recallTag: manualTag } = 提取剧情回忆标签(input);
  let recallTag = manualTag;

  if (应触发召回(cleanInput, state.mem, config)) {
    const candidates = 预筛候选(cleanInput, state.mem, config.完整原文N);
    const corpus     = 构建语料(state.mem, config.完整原文N, candidates);
    let parsed = 本地回退(candidates);
    try {
      const raw = await recallApi(COT, 玩家输入+语料, { temperature: 0.2 });
      parsed = 解析(raw).有结果 ? 解析(raw) : 本地回退(candidates);
    } catch { /* 用本地回退 */ }

    recallTag = 构建标签(parsed, state.mem);
    if (!config.静默确认) {
      await 弹窗确认(预览);          // 未确认则取消发送
    }
  }

  const ctx = 构建上下文({
    禁用短期记忆: Boolean(recallTag),
    禁用中期长期记忆: Boolean(recallTag),
    世界书附加文本: [cleanInput, recallTag || ''],
    即时剧情回顾: `【即时剧情回顾】\n${历史}\n\n【剧情回忆】\n${recallTag || ''}`,
  });

  const res = await 主剧情API(ctx, cleanInput);
  回合收尾(state.mem, gameTime, cleanInput, res, config);
}
```

## 十二、注意事项

- 召回 API 与主剧情 API 独立配置、独立失败处理；召回失败绝不能阻塞主剧情（回退本地）。
- 每回合写入回忆档案会让库线性增长：靠"滑动窗口 + 分层压缩"控制，不靠召回裁剪。
- 若要做"按角色提及召回"：先角色名/别名命中检测 → 对该角色条目加权 → 允许提前触发；其余链路不变。
- 世界书条目关键词命中用**小写归一化**的语料匹配（extraTexts 参与 corpus），别把 recallTag 直接塞进世界书注入文本。
