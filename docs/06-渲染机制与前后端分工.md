# 前端渲染机制：iframe 楼层注入 + 前端/伪后端分工

> 本文档是架构文档的续篇，深入讲解：
> - 这张卡的前端（Vue 界面）是通过什么机制渲染到 SillyTavern 页面上的（具体到代码级）
> - "前端 / 伪后端"分别是什么、如何分工

---

## 13. 渲染总览

前端**不是**在酒馆页面里直接挂组件，而是：

```
SillyTavern 页面 (#chat)
  └─ 一个"虚拟楼层" <div class="mes" data-tq-visual-zero="true">   ← 游戏 UI 楼层
       └─ .mes_text
            └─ #tangquan-game-ui-host   （宽度 min(100%,1366px) 的容器）
                 └─ <iframe srcdoc="<!doctype html>..." title="未开之花">
                      └─ 挂载 Vue 应用（createApp(根组件).mount(iframe body)）
```

一句话：**把 Vue 应用装进 iframe，把 iframe 装进一个克隆出来的消息楼层，把这个楼层追加到聊天末尾**。

## 14. 代码级实现（index.js）

### 14.1. 关键常量

```js
const m = '#chat > .mes[data-tq-visual-zero="true"]';  // 虚拟 UI 楼层选择器
const p = 'tangquan-game-ui-host';                     // iframe 容器 id
```

### 14.2. 找/建"虚拟楼层"（函数 `y` @728600）

```js
function y(e) {
  const t = $(m);                        // 已存在虚拟楼层？
  if (t.length > 0) return t.slice(1).remove(), t.first()
      .attr('data-tq-visual-zero','true');

  // 不存在：优先定位到指定楼层 e，否则取最后一条非虚拟消息楼层
  const n = $(`#chat > .mes[mesid="${e}"]:not([data-tq-visual-zero="true"])`).first()
         || $('#chat > .mes:not([data-tq-visual-zero="true"])').last();
  // 克隆它（或新建空 .mes），标记为虚拟 UI 楼层
  const r = n.clone(!1,!1) || $('<div class="mes"><div class="mes_block"><div class="mes_text"></div></div></div>');
  return r.removeAttr('id').removeAttr('style')
      .attr('data-tq-visual-zero','true').attr('mesid','0')
      .appendTo('#chat');
}
```

要点：
- **克隆最后一条消息楼层**，不是新建空白元素——克隆后清掉 id/style，打上 `data-tq-visual-zero` 标记，`mesid='0'` 不参与聊天编号；
- 若已有虚拟楼层则复用（只留一个，多余的删除）。

### 14.3. 定位挂载楼层（`getUiMountElement` @736076 + `h` @728600）

```js
getUiMountElement: function () {
  const n = h(e.settings);                       // 找"挂到哪个楼层"
  const a = n?.message_id ?? Math.max(0, getLastMessageId()); // 默认最后一条
  const o = y(a);                                // 得虚拟楼层元素
  o.removeAttr('data-tq-placeholder').attr('data-tq-ui-mounted','true');
  const s = B(a);                                // 取 .mes_text（没有则新建）
  let i = s.children(`#${p}`).first();           // p = 'tangquan-game-ui-host'
  if (i.length === 0) {
    s.empty();
    i = $('<div>').attr('id', p)
         .css({ width:'min(100%, 1366px)', margin:'0 auto',
                overflow:'hidden', background:'#100b08' }).appendTo(s);
  }
  return i[0];                                   // 返回容器，iframe 挂这里
}
```

`h` 找楼层的规则（`mirrorMode`）：
- `'latest_message'`：直接取最后一条消息楼层；
- 默认：在 `0-${lastMessageId}` 里取**最后一条 assistant（AI）消息**楼层。

### 14.4. 创建 iframe 并挂载 Vue（挂载函数 @1223900）

```js
const d = window.parent.document.createElement('iframe');
d.setAttribute('script_id', getScriptId());
d.setAttribute('frameborder','0'); d.setAttribute('title','未开之花');
d.setAttribute('allow','fullscreen'); d.allowFullscreen = true;
d.style.cssText = 'display:block;width:100%;aspect-ratio:16/9;border:0;background:#100b08;';
d.srcdoc = '<!doctype html><html><head><meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover"></head><body></body></html>';

d.addEventListener('load', () => {
  const r = d.contentDocument;
  r.documentElement.style.cssText = 'width:100%;height:100%;margin:0;overflow:hidden;';
  r.body.style.cssText = 'display:grid;place-items:center;width:100%;height:100%;...background:#100b08;';
  // 把父页面 head 的 <style> 克隆进 iframe（继承酒馆主题样式）
  s = $('<div>').attr('script_id', getScriptId())
       .append($('head > style', document).clone()).appendTo(r.head).destroy;
  // 挂 Vue 根组件
  n = createApp(根组件, { services: g, onClose: k }).use(pinia).mount(r.body);
});
l.appendChild(d);   // l = getUiMountElement() 返回的容器（#tangquan-game-ui-host）
```

### 14.5. 视口自适应（`SC` @1221932）

`ResizeObserver` + `window.parent` 的 resize/orientationchange/visualViewport 监听：
- 桌面：iframe 宽 `min(容器宽, 1366)`、高 `9/16 宽`，`aspect-ratio: 16/9`；
- 手机横屏/竖屏：按对应比例取高；
- 结果写 `data-viewport-mode`（desktop / mobile-landscape / mobile-portrait），父容器同步标记。

### 14.6. 镜像/隐藏（zeroLock + beautifier）

- 虚拟楼层标记 `data-tq-visual-zero="true"`；
- CSS（`#chat.tangquan-zero-lock[data-tq-hide="true"]`）把**非 UI 楼层隐藏、UI 楼层显示**——游戏界面全屏化时玩家只看到游戏楼层；
- AI 流式输出（`STREAM_TOKEN_RECEIVED`）也镜像到该楼层（`B(n).html(...)`），游戏界面实时显示 AI 回复；
- `MESSAGE_SENT` 时把玩家输入镜像到游戏界面（beautifier）。

## 15. 前端 / 伪后端分别是什么

### 15.1. 分工总表

| 角色 | 是什么 | 位置 | 职责 |
|---|---|---|---|
| **前端（真）** | iframe 里的 Vue 应用（根组件 + Pinia + 全部 UI 组件） | `零层美化/index.js`（前端 bundle） | 渲染游戏界面（老板/游客/服务员）、处理玩家交互、本地解析 AI 回复、立绘/背景渲染、把状态写回伪后端 |
| **伪后端** | **SillyTavern 酒馆 + 酒馆助手 + MVU 变量系统** | 酒馆宿主（不在 index.js 里） | 状态权威源（`stat_data`/`display_data`）、世界书存档、AI 请求执行、事件广播、持久化 |

### 15.2. 关键结论

1. **这张卡没有真正的后端服务器**。"伪后端"就是酒馆宿主本身。
2. **前端 = 表现层 + 协议层**：
   - 表现层：UI、交互、立绘、背景、楼层注入（本文档）；
   - 协议层：把 AI 输出解析成状态变更（`parseTangquanAiMessage` + MVU `_.set`）、把玩家操作翻译成 `generate()` 请求。
3. **伪后端 = 状态权威 + 执行器**：
   - 状态全存 `stat_data`/`display_data`（MVU），前端不自己持持久化状态；
   - AI 请求由酒馆发（`generate`），前端只组装输入；
   - 存档 = 写世界书条目（`tangquan-save-v1`）；
   - 同步 = 酒馆聊天/世界书机制。
4. **为什么这么设计**：前端 0 持久化、0 服务器、0 跨端状态管理——天然多端同步、天然可存档、天然依赖酒馆生态（事件/MVU/预设），代价是**强绑定酒馆助手 + MVU + 特定预设**（见 05 避坑指南）。

### 15.3. 数据流（一图流）

```
玩家在 iframe 界面操作
   ↓ 前端（表现层）
组装 generate() 请求（chat_history 覆盖 + injects + 预设 + 临时世界书）
   ↓ 伪后端（酒馆）
AI 请求执行 → 原始输出返回
   ↓ 前端（协议层）
parseTangquanAiMessage 解析 → 正文/分页/变量更新指令
   ↓ 伪后端（MVU）
_.set 更新 stat_data → 事件广播
   ↓ 前端（表现层）
读最新状态 → 重渲染 UI / 立绘 / 背景
```
