# 从零实现指南：造一个同类型的"前端同层卡"

> **本文档是规格，不是考古报告。** 面向一个零背景的 agent/开发者：照着它可以实现一套与汤泉卡同架构的"前端同层卡"（UI 注入 + AI 请求 + 状态持久化）。
> 阅读顺序：先读 01 架构总览建立心智 → 本指南按"从零搭建"顺序给出可执行步骤 → 卡壳时回查对应机制文档。
> 本文档只依赖：SillyTavern + 酒馆助手（Tavern Helper / JS-Slash-Runner）。**不需要任何其它运行时。**

## 57. 前置：运行环境与 API 契约（最关键的一章）

### 57.1. 运行模型（决定了整个架构怎么写）

**真实运行位置不是主窗口，而是酒馆助手创建的隐藏 iframe**（关键！）：

```
角色卡 JSON:
  data.extensions.tavern_helper.scripts = [{
    type: 'script', enabled: true, name: '...', id: '<uuid>',
    content: "import 'https://.../your-index.js'",   // ← 一行 import 语句
    button: { enabled: true, buttons: [...] },
    data: { ... }                                      // 可携带自定义状态
  }]

酒馆助手加载流程（JS-Slash-Runner 源码，src/panel/script/iframe.ts + predefine.js）：
  1. 角色卡 data.extensions.tavern_helper 读入（setting_field = 'tavern_helper'）
  2. 脚本被渲染成 <iframe id="TH-script--{name}--{id}" v-show="false">（隐藏）
  3. iframe 的 srcdoc = createSrcContent(content)：
       <body>
         <script src="parent_jquery_url">     // 父窗口的 $ (jQuery)
         <script src="predefine_url">         // ← 关键：把父窗口全局注入本 iframe
         <script type="module">               // ← 你的 content（import 语句）在此执行
           import '.../your-index.js'
         </script>
       </body>
  4. predefine.js 把父窗口（酒馆主页面）的这些全局注入 iframe 的 window：
       _ (lodash) / EjsTemplate / TavernHelper / YAML / showdown / toastr / z (zod)
       SillyTavern（含 getContext + writeExtensionField 覆盖）
       Mvu（getter 转发到 window.parent.Mvu）
  5. 因此你的脚本在 iframe 里"裸调" generate / createChatMessages / tavern_events / $ / z
     实际用的是注入后的 iframe 全局，不是主窗口全局——但用法完全一样，无感
```

**结论（写代码时记住）**：
- 你的 index.js 运行在**酒馆助手隐藏 iframe** 的 `<script type="module">` 里，天然是 ES module（顶层 `await import()` 可用）；
- 裸调 `generate` / `SillyTavern.*` / `tavern_events` / `z` 都可用（predefine 注入）；
- 要访问**主窗口**的真实全局/DOM（如 `window.parent.Mvu`、`#chat` 楼层容器），用 `window.parent.xxx`——同源 srcdoc iframe，直接可读；
- 你的 UI = Vue 应用，再装一层 srcdoc iframe，**iframe 作为"0 层楼层"挂进聊天流**：
  - 挂载容器 = 一个克隆自 `#chat .mes` 的楼层元素（`data-tq-visual-zero="true"` 标记、`mesid=0`），由 `getUiMountElement()` 提供，插在聊天流顶部；
  - iframe 的 `srcdoc` 是空 HTML，`load` 后再 `createApp(..., { services, onClose }).mount(r.body)`；
  - 用 `MutationObserver` 监听 `window.parent.document.querySelector('#chat')`，若 UI 楼层脱离 DOM 自动挂回（`window.parent.document` = 主窗口）；
  - iframe 内用 `window.parent` 访问酒馆主窗口（含上面那层隐藏 iframe 注入的全局），推荐通过 props/services 注入避免裸调。

**两条硬依赖**（缺失则初始化失败并提示）：
1. 酒馆助手（Tavern Helper）→ 提供 `window.TavernHelper`（generate/eventOn/变量/世界书全套）；
2. MVU（MagVarUpdate）→ 提供 `window.parent.Mvu`（`Mvu.parseMessage` 解析 `<UpdateVariable>`），可用 `waitGlobalInitialized('Mvu')` 等待。

> ⚠️ 此前版本文档误写为"运行在主窗口全局作用域"。真实是**隐藏 iframe + 全局注入**，两者对外表现几乎一致，但影响两点：① 脚本内 `window` 不是主窗口，DOM 查询要走 `window.parent`；② iframe 卸载（`pagehide`/清理）时脚本要自清理挂载在父窗口的全局（如 `delete window.parent.tangquanZeroLayer`）。

### 57.2. 核心 API 契约（来自 JS-Slash-Runner 官方 .d.ts，字段精确）

**① generate —— 唯一 AI 请求原语**

```ts
interface GenerateConfig {
  user_input?: string;          // 玩家输入（原样传，不加前缀；不传则用提示词模板）
  should_stream?: boolean;      // true=流式（事件 STREAM_TOKEN_RECEIVED_FULLY/INCREMENTALLY）
  should_silence?: boolean;     // true=静默（停止按钮不中断，用 generation_id 停止）
  overrides?: Overrides;        // 覆盖提示词：
  //   { char_description?:string, char_personality?:string, scenario?:string,
  //     persona_description?:string, world_info_before?:string, world_info_after?:string,
  //     dialogue_examples?:string, jailbreak?:string, system_prompt?:string,
  //     chat_history?: { with_depth_entries:boolean, prompts: RolePrompt[] } }
  injects?: Omit<InjectionPrompt,'id'>[];  // 动态注入（in_chat 定位），见下
  max_chat_history?: 'all' | number;       // 聊天历史条数上限
  // 模型参数覆盖（'same_as_preset' | 'unset' | 数值）：
  temperature?, top_p?, top_k?, frequency_penalty?, presence_penalty?, max_tokens?, ...
}
interface InjectionPrompt {
  role: 'system'|'user'|'assistant';
  content: string;
  position: 'in_chat';          // 注入到聊天历史中间
  depth: number;                // 距当前消息的深度（0=最新）
  order?: number;               // 同 depth 排序
  should_scan?: boolean;        // 是否参与世界书扫描
}
// 返回 Promise<string>（最终文本）；流式时同时发 GENERATION_STARTED/ENDED 事件
```

**② eventOn / 事件系统（监听酒馆生命周期）**

```ts
eventOn(event_type, listener): EventOnReturn  // 返回含 .stop() 的句柄（dispose 时用）
eventMakeLast(...)  // 注册到监听器末尾（最后执行）
// 常用事件（tavern_events.*）：
MESSAGE_SENT/RECEIVED/EDITED/DELETED/SWIPED/UPDATED, CHAT_CHANGED,
GENERATION_STARTED/STOPPED/ENDED, APP_READY, SETTINGS_LOADED, ...
// iframe 事件（generate 专用）：GENERATION_STARTED/ENDED, STREAM_TOKEN_RECEIVED_FULLY/INCREMENTALLY
```

**③ 聊天楼层 API（读历史/写楼层）**

```ts
getChatMessages(range: string|number, { role?, hide_state?, include_swipes? }): ChatMessage[]
// range: '0-{{lastMessageId}}' 全部；-1 最新；负数=深度
// role: 'all'|'system'|'assistant'|'user'; hide_state: 'all'|'hidden'|'unhidden'
getLastMessageId(): number
createChatMessages(msgs: {role, message, data?, extra?, name?, is_hidden?}[], { insert_before?: number|'end', refresh?: 'none'|'affected'|'all' }): Promise<void>
setChatMessages(msgs: {message_id, data?, extra?}[], { refresh? }): Promise<void>   // 更新楼层变量
deleteChatMessages(message_ids: number[], { refresh? }): Promise<void>
```

**④ 变量 API（游戏状态存取）**

```ts
getVariables({ type: 'chat'|'global'|'message'|'script', message_id? }): Record<string, any>

deleteVariable(name, { type? }): void
// MVU 扩展：Mvu.parseMessage(message, parseBase) 执行 <UpdateVariable><Analysis/><JSONPatch/></UpdateVariable>
```

**⑤ 世界书 API（状态注入 / 存档载体）**


## 58. 从零搭建：目录与骨架

```
your-card/
  ├─ index.js          # 入口：import 依赖 → 初始化控制器 → 渲染 UI（构建产物，单文件）
  ├─ src/
  │   ├─ main.js       # 入口逻辑：g.open() 初始化链
  │   ├─ api.js        # 酒馆 API 薄封装（getChatMessages/generate/eventOn...）
  │   ├─ services/     # 控制器：save / log / preset / worldbook / zeroLock
  │   ├─ stores/       # Pinia stores（UI 状态）
  │   ├─ parser.js     # AI 回复解析（正文/变量/标签剥离）
  │   └─ ui/           # Vue 组件（App.vue / 各页面）
  ├─ vendor/           # 本地化依赖：klona / pinia / vue / Mvu bundle（避免 CDN）
  └─ chara-card.json   # 角色卡 JSON（tavern_helper 引 index.js）
```

**最小可运行骨架（index.js 顶部）**：

```js
// ① CDN 依赖（离线化时改为 import './vendor/klona.js' 等）
import { klona } from 'https://testingcf.jsdelivr.net/npm/klona/+esm';
import { createPinia, defineStore } from 'https://testingcf.jsdelivr.net/npm/pinia/+esm';

// ② 校验运行环境（缺失直接报错，不静默）
const hasTavernHelper = typeof generate === 'function' && typeof eventOn === 'function';
const hasMvu = !!(window.parent?.Mvu);
if (!hasTavernHelper) throw new Error('需要酒馆助手（Tavern Helper）');

// ③ 初始化链（g.open 模式）
async function init() {
  await waitGlobalInitialized('Mvu').catch(() => {});   // 等 MVU（10s 超时降级）
  const controller = createController({ api, log });     // 见 §60
  mountUi(controller);                                   // 见 §61
  window.parent.__YOUR_CARD__ = controller;              // 挂全局（排查/卸载）
  window.addEventListener('pagehide', () => controller.dispose());
}
init();
```

## 59. 控制器骨架（services 模式）

> 汤泉卡的 `zeroLayer` 控制器 = 一个对象，聚合所有能力；Vue 通过 `props.services` 拿它。**这是"前端/伪后端分工"的核心**（见 06 文档）。

```js
function createController({ api, log }) {
  const zeroLock = {  // UI 楼层占用锁（见 06 文档）
    getUiMountElement() { /* 找/克隆 #chat 里的虚拟楼层 */ },
    releaseUiMountElement() { /* 归还 */ },
    applyAll() { /* 同步虚拟楼层可见性 */ },
  };
  const save = { /* 存档系统：worldbookSave（见 04 文档 §9）*/ };
  const preset = { /* 输出格式：updatePresetWith 启停 🎯/💭 段（见 02 文档 §6.3）*/ };
  const worldbook = { /* 临时世界书条目（见 11 文档）*/ };
  const services = { log, zeroLock, save, preset, worldbook };
  return {
    services,
    async dispose() { /* 卸载：事件 .stop() + 观察器 disconnect + 移除全局 */ },
  };
}
```

## 60. UI 渲染骨架（iframe 楼层注入）

> 完整机制见 06 文档。核心步骤：

```js
function mountUi(controller) {
  const parentDoc = window.parent.document;
  const host = controller.services.zeroLock.getUiMountElement();  // 虚拟楼层 .mes_text
  const iframe = parentDoc.createElement('iframe');
  iframe.setAttribute('title', '你的卡名');
  iframe.style.cssText = 'display:block;width:100%;aspect-ratio:16/9;border:0;';
  iframe.srcdoc = '<!doctype html><html><head><meta name="viewport" content="width=device-width,initial-scale=1"></head><body></body></html>';
  iframe.addEventListener('load', () => {
    const doc = iframe.contentDocument;
    const app = createApp(App, { services: controller.services }).use(createPinia());
    app.mount(doc.body);
  });
  host.appendChild(iframe);
}
```

**要点**：
- iframe 用 `srcdoc`（同源 `about:srcdoc`），**无需代理脚本**——需要酒馆 API 时用 `window.parent.xxx` 或经 `props.services` 注入；
- 虚拟楼层 = 克隆最后一条 `.mes`，打 `data-tq-visual-zero="true"` + `mesid="0"`，只保留一个；
- 全屏：iframe 的 `allow="fullscreen"` + `allowFullscreen`，配合 `requestFullscreen`（手机降级 fixed 覆盖，见 09 文档 §34.5）；
- 页面卸载（pagehide）时必须 `controller.dispose()` 防残留（见 07 文档 §23）。

## 61. 分步验收清单（完成定义）

> 每步有明确"做完了"的判定。**建议按顺序做，每步验证通过再进下一步。**

| # | 步骤 | 完成判定（验收） |
|---|---|---|
| 1 | 环境检测 | 缺酒馆助手时页面报错"需要酒馆助手"，而非静默失败 |
| 2 | 渲染出 UI | 聊天末尾出现虚拟楼层，iframe 内 Vue 界面可见、可交互 |
| 3 | 发一次 AI 请求 | 点按钮 → `generate({user_input})` → 收到回复文本（控制台或 UI 显示） |
| 4 | 写楼层 | `createChatMessages([{role:'user',...},{role:'assistant',...}])` 后聊天出现两条楼层 |
| 5 | 读历史 | `getChatMessages('0-{{lastMessageId}}')` 能取到刚写的楼层 |
| 6 | 状态持久化 | 写变量 `getVariables({type:'chat'})` 可见；刷新页面后仍在 |
| 7 | 变量更新 | 回复含 `<UpdateVariable>` → `Mvu.parseMessage` 执行 → stat_data 变化 |
| 8 | 卸载干净 | 触发 `dispose()` 后无事件残留、无 iframe、无全局（控制台检查） |
| 9 | 存档/读档 | 存档后读档，状态+聊天楼层完整还原（checksum 校验通过） |

## 63. 已知坑（先看再动手）

1. **别直接操作酒馆楼层 DOM**（`#chat` 会被渲染流程重排）——用 `createChatMessages`/`setChatMessages` 官方 API；
2. **`z` 自由全局陷阱**：minified 里 `z` 可能是 zod 且无 import——引用前确认作用域（见 05 文档 §11.5）；
3. **CDN import 要离线化**：`import '.../npm/xxx'` 在生产卡里改成 vendor 本地文件，否则断网即挂（09 §33.1）；
4. **事件监听必须收集句柄**：`eventOn(...)` 返回 `.stop()`，dispose 时逐个调用，否则页面残留（07 §23）；
5. **`generate` 不要并发**：全部走串行队列（`enqueueAiGeneration`），防并发污染（09 §34.1）；
6. **MVU 是软依赖**：`waitGlobalInitialized('Mvu')` 超时后要有降级（`replaceVariables` 直接写），不能卡死初始化；
7. **楼层 extra 别塞大对象**：会写进聊天文件膨胀；用 `extra` 存轻量标记（sceneId/traceId），重数据走变量/世界书。
