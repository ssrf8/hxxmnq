## 18. 事件注册机制：包装 + stop 收集 + 统一解除

前端所有酒馆事件订阅走同一模式——包装函数把 `.stop` 收进数组，dispose 时批量解除：

```js
// zeroLock（零层/视觉镜像）@734000
function T(e, t, n = !1) {
  s.push((n ? eventMakeLast(e, errorCatched(t)) : eventOn(e, errorCatched(t))).stop);
}
// beautifier（楼层高亮）@726000
function o(e, t, a = !1) {
  n.push((a ? eventMakeLast(e, errorCatched(t)) : eventOn(e, errorCatched(t))).stop);
}
```

- `eventOn(e, cb)` 普通注册；`eventMakeLast(e, cb)` 注册到事件链**末位**（第三参 `!0`）；
- `errorCatched(t)`：回调异常包装，防止单个回调崩掉拖垮事件链；
- `.stop` 存数组 → dispose 时 `n.forEach(e=>e())` 逐个解除。

### 三组订阅点

| 订阅点 | 事件数 | 用途 |
|---|---|---|
| beautifier（@726000） | 11 个（MESSAGE_SENT/RECEIVED/SWIPED/EDITED/UPDATED/DELETED/渲染/生成/CHAT_CHANGED） | 重算楼层高亮（`data-tangquan-beautify-reason`） |
| zeroLock（@734000） | 13 个（含 STREAM_TOKEN_RECEIVED，唯一普通 eventOn 顺序注册） | 状态标记 + 游戏界面镜像同步 |
| App.vue 游戏 UI | 4 个（MESSAGE_DELETED/SWIPED/EDITED/UPDATED） | MVU/结果同步，句柄挂 `window.__tqCustomerChatEventStops` |
| 主入口按钮 | 1 个（`getButtonEvent('打开未开之花')`） | 打开游戏界面 |

## 19. 重点：监听"用户发送后"的完整回调流程

玩家发送 → 酒馆派发 `MESSAGE_SENT` → 前端**两处监听并行**：

```
玩家在 iframe 输入 → 前端 submit → generate() + createChatMessages 手动建楼层
                                                         ↓
                                   酒馆派发 tavern_events.MESSAGE_SENT
                                                         ↓
                 ┌──────────────────────────────┬──────────────────────────────┐
                 ▼ beautifier（@726000）        ▼ zeroLock（@734000）           │
    o(MESSAGE_SENT, ()=>r('用户输入'), !0)     T(MESSAGE_SENT, (t,n)=>{         │
       → 120ms 防抖重算楼层高亮                   markStatus({isGenerating:!0})  │
       （给当前楼层加 data-tangquan-              setTimeout(0, ()=>{           │
         beautify-reason 类）                        if (enabled && !manualReveal
                                                       && previewUserInput) {
         ──┐                                        b(t,{role:'user'}) 取用户楼层
            │                                       B(t).html(formatAsDisplayedMessage(
            │                                         a, {message_id:t}))
            │                                       → 克隆用户消息写进零层 .mes_text
            │                                       → y(t).attr('mesid','0')
            │                                         .attr('data-tq-visual-zero','true')
            │                                         .attr('data-tq-source',t)
            │                                         .attr('data-tq-preview','user')
            │                                       → M() 应用隐藏锁
            │                                    })
            │                                  }
            └──────────┬─────────────────────────┘
                       ▼
      新克隆的 DOM 又触发 beautifier 的 MutationObserver
      → 再防抖一次（80ms）→ 高亮/属性保持一致
```

完整链路：事件派发 → 两回调并行（高亮重算 + 克隆用户层进零层预览）→ 新 DOM 触发 MutationObserver 再同步 → 镜像核心 `N()`（`refreshOneMessage` → `k(s)` 标记 → `markStatus({lastMirroredId...})`）。

> **重要**：`MESSAGE_SENT` 不拦截、不改写输入（改写发生在更上游——前端自己的 `generate()` 请求组装，见 02 文档 §6）。监听器只做状态同步 + 视觉镜像。

## 20. 生成期事件：从 token 流到界面

```
GENERATION_STARTED  → isGenerating=true + M()（应用隐藏锁）
STREAM_TOKEN_RECEIVED（流式，每 token）→ B(n).html(formatAsDisplayedMessage(累计全文))
                    → k(n) 标记 → M()
GENERATION_STOPPED  → isGenerating=false + 防抖同步
GENERATION_ENDED    → isGenerating=false + 防抖同步
MESSAGE_RECEIVED    → 非 quiet/command/extension 来源：isGenerating=false + 防抖同步
```

流式镜像（唯一普通 eventOn 顺序注册，保证先于其它处理）：

```js
T(tavern_events.STREAM_TOKEN_RECEIVED, t => {
  if (!enabled || manualReveal || !streamPreview || !t.trim()) return;
  const n = Math.max(0, getLastMessageId());
  try { B(n).html(formatAsDisplayedMessage(t, {message_id:n})), k(n), M(); }
  catch { B(n).text(t); }   // 异常降级纯文本
});
```

## 21. DOM 观察（5 个）

| 观察器 | 目标 | 回调 | 解除 |
|---|---|---|---|
| beautifier MO | `#chat`（childList+subtree+attributes，只盯 `data-tq-source`/`data-tq-visual-zero`） | 80ms 防抖高亮 | dispose |
| zeroLock MO | `#chat`（childList，不深入） | `M()` 重应用隐藏锁 | dispose |
| App.vue MO | 父页面 `#chat`（`new parentWindow.MutationObserver`） | 过滤镜像层（排除 `data-tq-visual-zero`）→ 2800ms 防抖 → `runBackgroundSync`（游客/服务员结果 + MVU 对账 + 存档标记） | onBeforeUnmount |
| gameUi 保活 MO | 父页面 `#chat` | 检测游戏 iframe 脱离零层则重新挂回（另配 `setInterval(C, 1e3)` 兜底） | close/dispose |
| SC() ResizeObserver | 宿主元素 | iframe 宽高/视口模式同步到 `window.parent` | open/close/dispose |

## 22. Vue watch 与 window 生命周期

- **zeroLock 深 watch settings**（核心副作用源）：`watch(()=>({...e.settings}), ..., {deep:true})`——设置一变就重应用样式/隐藏锁；
- 组件级 watch：`busy`（游客消息草稿校验）、`tutorialTarget`（引导滚动）、TimePicker/TutorialOverlay 等；
- **window 监听**：App.vue 三对 `bind/unbind`（视口 resize、全屏 fullscreenchange、输入活动 autoSave.noteActivity）；loading overlay 存盘时挂 `beforeunload` 拦截刷新；主入口挂 `pagehide`。

## 23. 清理链（无残留的关键）

```
pagehide → b()（f 标志防重入）
  → v.dispose() = A.stop() + updateScriptButtonsWith(移除按钮)
      + g.dispose() + u.dispose() + n.dispose() + o.dispose() + r.dispose()
  → 各层内部再递归 disconnect / stop / unbind
  → delete window.parent.tangquanFrontend / tangquanZeroLayer / tangquanZeroLayerEmergencyDisable
```

**全景一句话**：所有酒馆事件订阅用 `eventOn`/`eventMakeLast` + `.stop` 收集；所有 DOM 观察器记录引用；所有 window 监听配对称 unbind；入口统一 `dispose` + `pagehide` 兜底——前端卸载后酒馆页面零残留。
