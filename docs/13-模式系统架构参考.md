# 模式系统架构参考（老板/游客/服务员）

> **定位：架构参考，非玩法复刻手册。** 本文档讲"三种模式在架构上如何组织"，提炼可复用到其它"前端同层卡"的通用模式：状态如何存、模块如何激活/卸载、AI 请求如何调度、世界书/楼层如何联动。
> 具体玩法数值（价格、评级表、按钮操作）仅作示例一笔带过，不做复刻依据。
> 证据：`decoded.txt` 行号 + `index.js` 字节偏移。

---

## 50. 通用架构模式：模式 = 一组"可插拔模块"的开关

**核心心智：一种模式 = 状态块 + 变量块 + 世界书条目 + UI 组件树 四件套的切换。** 这套模式不依赖汤泉玩法，任何"多模式前端同层卡"都可复用。

```
activeMode (stat_data，zod 枚举，非法回退默认值)
   │
   ├─ 状态对象     ：bossState / customerState / waiterState（ref<State>，含存档提取/归一化）
   ├─ MVU 变量块   ：activateXxxMvuBlocks(blockIds, context) 进入时挂载，deactivateXxxMvuBlocks 退出时卸载
   ├─ 世界书条目   ：syncModeEntries(mode, slotId) 启停 boss.rules.* / customer.rules.* / waiter.rules.*
   └─ UI 组件树    ：监听 activeMode 切换 Vue 组件（BossPlay / CustomerPlay / WaiterPlay）
```

**为什么这是通用模式**：
- 模式之间**零硬编码耦合**——只通过 `stat_data.activeMode` + 各自命名空间的条目/变量交互；
- 新增一个模式 = 复制四件套，不碰其它模式代码；
- 存档/读档只关心 `activeMode` + 各模式状态对象（`extractSavedXxxState`），与玩法无关。

## 51. 状态层模式：一个 ref + 归一化 + 存档提取

三种模式的状态对象结构不同，但**架构形态一致**：

| 层 | 模式 | 说明 |
|---|---|---|
| 定义 | `makeBossPageState()` 等 | 默认状态工厂（ref 初始化用） |
| 归一化 | `normalizeXxxState` / `recalculateXxxState` | 读档/外部改坏后修正（缺失字段补默认） |
| 存档提取 | `extractSavedBossState('前端数据.老板页面')` | 从 stat_data 深路径恢复状态对象 |
| 变更入口 | `runBossMutation(mutator)` 等 | 统一包装：改状态 → 同步 MVU → 触发自动保存 |

**要点**：状态对象**只在内存**（ref），持久化走 MVU `stat_data`（03 文档 §8），**不自己落盘**。玩法字段（员工/项目/指名/评级……）只是该模式命名空间下的数据，架构上与"存档写哪、怎么恢复"解耦。

## 52. AI 请求调度模式：每模式一个"请求工厂"集合

通用形态：**每种玩法动作 → 一个请求工厂 → 统一进 generate 队列 → 统一解析/落地**。

```
动作（进入场景/面试/签约/结算/每日安排…）
  → 请求工厂：makeXxxGenerationInjects / makeXxxDailyReportInjects / makeDailyGenerationOverrides
  → enqueueAiGeneration(label, task)  串行队列（09 文档 §34.1）
  → generate({ user_input, should_stream, overrides, injects })
  → getGenerationText → 本地解析（parseTangquanAiMessage / applyXxxDailyReport）
  → createChatMessages 双楼层落地（08 文档 §32.1）
```

**请求类型按"用途"分三类**（三模式共用这套分类）：

| 类型 | 特点 | 例子 |
|---|---|---|
| 现场互动 | `should_stream:true`、chat_history 覆盖、`customer/waiterInjects` | 现场对话/AIRP 正文 |
| 后台生成 | `should_stream:false`、`max_chat_history:0`、`makeDailyGenerationOverrides()` 全清空、`user_input:''` | 每日安排/经营日报/AI 候选 |
| 输出格式切换 | 每次请求前 `presetOutputFormat.setFormat(...)` 选 🎯 段 | galgame / airp / message / daily |

**injects 差异**（`customerInjects` vs `waiterInjects`，decoded 5287-5363）：同一套输出格式模板（`Su` `[输出格式要求]`），差异只在**角色视角与场景事实**——架构上是一处 `scene.mode === '游客' ? customer : waiter` 分支，模板本身共享（03 文档 §7.2.1 全文）。

## 53. 时间与跨日服务（三模式共用）

**通用模式：游戏内时钟 + 跨日联动回调表**，与具体玩法无关。

```
真实时间 tick（setInterval 1s）→ 刷新"现实时间"展示 + 定时刷新逻辑（如招聘池）
游戏内时钟（stat_data: 时间/日期/营业日）→ 由跨日/结算/TimePicker 推进
TimePicker：目标早于当前 → crossesMidnight:true（先走跨日流程再设目标时间）
跨日联动：按 activeMode 查表执行（老板=结算+日报，游客=次日安排，服务员=下班结算）
```

实现位置：`tickRealTime`（decoded 3205）、`TimePicker.vue`（decoded 13942）、`planTangquanTimeTravel`（`./timeTravel` 模块）。

## 54. 错误处理与重试层（通用）

| 层 | 机制 | 通用性 |
|---|---|---|
| 操作包装 | `runAction`：catch → log+toast → finally 刷新 runtime | 任何用户动作复用 |
| AI 串行队列 | `enqueueAiGeneration`：所有 generate 排队 | 防并发污染 |
| 解析重试 | 候选/日报：记录 `已尝试生成/来源/问题`，失败降级 fallback，最多重试 2 次 | 生成类请求通用 |
| 外部依赖兜底 | MVU 超时 `Promise.race` / 轮询等待 / 无 MVU 降级 replaceVariables；日报本地 fallback | 依赖不可用时的降级路径 |
| 事务回滚 | 签约：失败回滚 MVU/世界书/残片三层 | 跨存储写操作通用 |

## 55. 参考速查：三模式的"架构指纹"

> 仅列架构相关差异；玩法数值不作为复刻依据。

| 维度 | 老板 | 游客 | 服务员 |
|---|---|---|---|
| 状态对象 | bossState（经济/员工/建筑/结算） | customerState（员工/项目/联系人/住宿） | waiterState（班次/客人/成长/评级） |
| MVU 块 | boss.*（管理/现场） | customer.* | waiter.service / waiter.growth |
| 世界书激活 | boss.rules.management / scene | customer.rules.* | waiter.rules.* |
| 现场请求 | 通用 dialogue/story | dialogue（顾客视角）+ story（额外/邀约） | story（员工服务视角） |
| 后台请求 | 经营日报 / AI 人才候选+签约人设 | 每日安排 | 每日客人安排 |
| 联系人 | — | 线上消息（kind:'message'，历史=前端内存会话） | — |
| 跨日动作 | 结算+日报+自动存档 | 住宿/指名天数-1+次日安排 | 日薪结算+次日安排 |
