# 临时世界书：动态条目启停与覆写机制

> 本文档专讲汤泉卡的"临时世界书"机制——**改的是当前聊天绑定的那份世界书文件，不是新建独立世界书**。
> 证据均带 `index.js` 字节偏移。
> 相关：10 文档 §36.3（发送前写入）、02 文档 §6.2（启停时机）、04 文档 §10（世界书结构）。

---

## 37. 核心心智：不是"创建/删除"，而是"启停 + 覆写"同一个预置条目

**条目本体永远预置在世界书里（空占位，enabled=False），前端只做两件事：**
1. 把目标条目 `enabled: true`；
2. 对"动态条目"（5 个 current 之一）**覆写 content** 为当前状态快照。

离开场景时反向操作：`enabled: false` + 清空 content（恢复空占位）。**世界书文件不增删条目、不新建文件**。

## 38. 世界书文件解析（resolveWorldbookName）

```js
// @841419 附近（save 模块闭包）
function i() { return getChatWorldbookName('current')?.trim() ?? '' }   // 当前聊天已绑定的世界书
async function l(e) { await rebindChatWorldbook('current', e); ... }   // 把世界书绑定到当前聊天
async function c() {  // = resolveWorldbookName
  const t = i();
  if (t) return t;                      // ① 聊天已绑定 → 直接用
  // ② 未绑定 → 用前端配置 worldbookName 尝试绑定
  // ③ 仍失败 → createWorldbook(n, []) 新建空世界书 → l(n) 绑定到当前聊天
}
```

- **唯一新建场景**：当前聊天没绑定任何世界书时，`createWorldbook` 建**空**世界书再 `rebindChatWorldbook('current', n)` 绑上（日志："已显式创建并绑定聊天世界书"）；
- 写入即落盘：`SillyTavern.saveWorldInfo(name, data, true)` + `reloadWorldInfoEditor` + `updateWorldInfoList`（@841349 `s` 函数）；
- 所以"临时"指的是**条目内容随场景启停/覆写**，不是临时文件。

## 40. 写入/清理机制（enableEntries / disableEntries / replaceTemporaryEntries）

```js
// enableEntries @1236336：把目标条目 enabled:true，动态条目（FC 集合内）覆写 content
updateWorldbookWith(name, e => e.map(e => {
  const t = RC(e);                      // 读条目 extra.tangquanEntryId
  if (!t || !ids.includes(t.id)) return e;
  const isDynamic = WC(t.id);           // FC.has(id) → 是否 5 个 current 之一
  return { ...e, enabled: true,
    content: isDynamic ? (contentMap[t.id] ?? '') : e.content,  // 动态条目才覆写内容
    extra: { ...e.extra, source: 'tangquan-runtime-worldbook-v1', tangquanEntryId: t.id } };
}), { render: 'immediate' });

// disableEntries @1236861：enabled:false，动态条目清空 content（恢复空占位）
// replaceTemporaryEntries @206349：diff 新旧集合 → 先 disable 旧 → 再 enable 新 → 记录 activeTemporaryEntryIds
```

- **打标**：`extra.source='tangquan-runtime-worldbook-v1'` + `extra.tangquanEntryId`，前端据此识别"我管的条目"，`enableEntries` **绝不误改** `common.*` 常驻条目内容；
- **空占位**：卡内预置 `<当前员工>\n</当前员工>` 骨架（enabled=False），前端只填内容不增删条目；
- **关闭时机**：离开现场 `replaceTemporaryEntries([], '离开现场')`（@220738）、返回标题 `disableModeWorldbookEntries`（@206434，关 mode 类 + 3 个 variable-rule）、切模式 `syncModeEntries`（@1236328）。

## 41. 完整生命周期（4 类调用点）

```
世界书条目永远预置（空占位，enabled=False）
   │
   ▼
进入场景 → replaceTemporaryEntries(场景条目)  → enable 区域/项目/员工/客人 + 覆写 content
   │
   ▼
发送消息 → requestSceneGeneration ③ 再次 replaceTemporaryEntries（@272304）
   │        （保活：确保当前场景条目 enabled + content 最新）
   ▼
场景内切换（换区域/换角色/开项目）→ replaceTemporaryEntries(新集合) → diff 关旧开新
   │
   ▼
离开现场/返回标题/切模式 → replaceTemporaryEntries([]) / disableModeWorldbookEntries
   │        全部 dynamic 条目恢复 enabled=False + 空 content
   ▼
（世界书文件里条目仍在，只是休眠）
```

全部 33 个 `replaceTemporaryEntries` 调用点归为 4 类：

| 类别 | 时机 | 示例 |
|---|---|---|
| 进入场景激活 | 切模式/进区域 | `area.current` + `character.current-employee` |
| 发送前保活 | 每次 `requestSceneGeneration` ③ | 确保场景条目 enabled + 最新 |
| 场景内切换 | 换区域/换角色 | diff 关旧开新 |
| 清理 | 离开现场/返回标题/切模式 | `replaceTemporaryEntries([], '离开现场')` |

## 42. 用户问答归档

- **Q：改写的是绑定的世界书还是新建？** A：改**当前聊天绑定的那份**（`getChatWorldbookName('current')`）；只有聊天从未绑定时才 `createWorldbook` 建空文件并绑定。
- **Q：只放当前内容吗？** A：对——5 个 current 条目只放**当前正在交互的那一个**区域/项目/员工/客人/候选人的**关键字段快照**；长篇静态设定在常驻条目里。
- **Q：进入场景创建、发送时调用、退出移除？** A：**基本正确，修正一点**——不是"创建/移除条目"，而是"启停 + 覆写"预置条目；"发送时调用"实际是**保活**（ensure 当前条目 enabled + content 最新），不是重复创建。
