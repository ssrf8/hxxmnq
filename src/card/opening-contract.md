# 继承序章与开场事务契约

开场界面先维护当前聊天的本地草稿：姓名、称谓/代词、外貌简述、庭园名称。预览和修改草稿不得写入 MVU，也不得把庭园标记为已经继承。

新聊天开始时：

1. 校验并冻结草稿与聊天 ID；
2. 发送一条带 `gensokyo_opening` 事务标记的正常玩家消息，并触发一次正文生成；
3. 正文只讲述祖父留下移动庭园的缘由、遗产的边界与代价，以及庭守钥即将带玩家穿过结界的过程；
4. 在玩家作出选择前，不得宣告继承成功，不得让玩家已经进入庭园，不得写入开场变量；
5. 正文必须停在庭守钥苏醒并等待玩家亲手接过的时刻；
6. 开场界面展示这段回复；只有玩家点击“接过庭守钥 · 继承庭园”后，才进入本地确认事务；
7. 本地事务从带标记的原始玩家消息解析资料，以其后最新 assistant 楼层为精确写入目标，从 `initial-state.json` 补齐共享默认状态；
8. 只覆盖玩家姓名、称谓、外貌、庭园名、庭守钥状态及 `meta.initialized`、`meta.opening_committed`，随后使用 `Mvu.replaceMvuData` 写入并立即复读；
9. 只有复读字段完全一致后才开放庭园，并允许数据库做可选归档。

继承确认必须幂等。相同资料重复提交直接视为成功；若当前聊天已用另一组资料完成开场，则拒绝静默覆盖。生成或写入失败时保留草稿和开场页，不推进时间、资源、关系或事件，并提供原地重试。

序章回复不得输出或假装完成 MVU 初始化。祖父可以通过遗信、旧录音或可信的回忆痕迹介绍庭园，但不得作为能即时替玩家作决定的幻影。其他幻想乡角色不得在继承确认前闯入序章。

继承完成后的第一次真实行动从玩家刚穿过结界、抵达荒废庭园的当下承接。变量模型不得再次初始化玩家资料或重复发放庭守钥。

旧聊天若已经存在带 `gensokyo_opening` 标记的 user 消息，继续使用同一恢复路径：显示其后最新 assistant 回复，并由玩家确认后写入开场字段。受限 LLM 修复只作为旧聊天的末级手段。

快速开始优先读取 Persona。缺失字段使用“中性称谓”和“无名庭园”，外貌可为空。叙事人称由玩家预设和实际输入决定。

验收必须覆盖：草稿无副作用、序章真实生成、生成前不继承、序章展示、显式确认后复读持久化、刷新恢复、重复点击、聊天切换、写入失败保留草稿、旧聊天兼容恢复，以及继承后的第一次真实行动。
