## 一、修复目标

本轮需要确认以下行为：

1. 角色首轮回复落盘后，GAL 不会重新显示“你来到了 XXX 面前，想说些什么”。
2. 无回复的失败事务保留“重试生成”；已有回复但结算失败时保留正文，并提供“重试本地结算”。
3. “修复”可以解除异常事务，不会让已落盘回复再次被草稿遮住。
4. 场景道具只在回复正式结算时扣除一次；失败、重试、刷新均不能免费使用或重复扣除。
5. 地图行动会把玩家正式位置写入目标区域，场景历史不会错误衔接到旧地点。
6. 月见温泉开场失败时会话会回滚，不留下幽灵活动。
7. 设施风险和行动结果只在回复完整结算后落地。

## 二、测试准备

- 使用测试聊天或测试存档，不要直接覆盖长期游玩档。
- 确认加载的 UI 版本为 `test-r34`。
- 保持 MVU 与额外变量模型正常启用。
- 建议打开原生聊天作为旁证；每轮同时观察原生楼层与 GAL 正文。
- 涉及故意断开生成服务的项目，测试后立即恢复连接。

记录格式：`通过 / 失败 / 无法测试`，失败时保留截图、原生聊天最后两层、GAL 状态提示和诊断导出。

### A01｜角色首轮聊天不回退草稿

1. 在地图点击任意在场角色，选择普通聊天。
2. 确认初始画面显示“你来到了 XXX 面前，想说些什么”。
3. 输入一条容易辨认的内容并发送，例如：“测试首轮回复，请只说一句天气。”
4. 等待回复与变量结算结束。

预期：

- 原生聊天存在一条玩家消息和一条非空 assistant 回复。
- GAL 显示该 assistant 回复，不重新显示初始草稿。
- 输入框不会恢复刚才已经发送的文字。
- 完整结算后“重新生成”可用。

### A03｜无回复失败后可以重试生成

1. 新开一次角色聊天，在发送前临时让模型请求失败（例如暂时断开 API）。
2. 发送一条消息，等待界面进入失败状态。
3. 恢复 API，点击“重试生成”。

- 失败时不会永久显示“回应中”。
- 界面出现“重试生成”，不会重复创建玩家楼层。
- 重试成功后只新增一条 assistant 回复。
- GAL 正常显示回复，事务最终恢复为可继续聊天状态。

### A04｜已有回复但结算失败的恢复

此项只有在能稳定制造 MVU/额外变量结算失败时执行。

1. 保证正文模型能生成，但临时让额外变量阶段或 MVU 写入失败。
2. 在角色聊天中发送消息并等待 assistant 正文出现。
3. 观察 GAL 状态，再恢复 MVU/额外变量能力。
4. 点击“重试本地结算”。

预期：

- assistant 正文始终留在 GAL，不回退初始草稿。
- 失败期间不能发送下一条消息，避免跨事务污染。
- 按钮文案为“重试本地结算”，不会再次调用正文模型。
- 结算恢复后按钮消失，聊天可继续。

结果：__________

### A05｜修复按钮不会恢复遮挡草稿

- “重新生成”不会只亮一下又立即熄灭；其状态应与当前最后一条 assistant 楼层一致。

### A06｜场景道具原子扣除与幂等

1. 记录一种场景聊天道具的初始数量 N。
2. 与角色聊天，选择该道具并发送一轮能明确使用道具的内容。
3. 回复结算后刷新 UI，再查看背包和场景道具上下文。
4. 如果能制造失败，分别在无回复失败、回复后结算失败时执行一次重试。

预期：

- 无回复失败时数量仍为 N。
- 回复完整结算后数量恰好为 N-1。
- 重试或刷新不会再次扣除，也不会恢复成 N。
- 模型正文使用了道具时，正式状态中一定存在同一场景道具记录。

### A07｜地图位置与跨场景连续性

- 后续道具或本地规则读取到的 `player.current_area_id` 与最后进入的区域一致。

### A09｜月见温泉失败回滚

1. 确认月见温泉当前没有活动会话。
2. 临时断开正文模型服务。

5. 再次进入温泉。

- 第一次失败后不残留进行中的温泉会话。
- 第二次可以正常启动，不提示已有会话或被旧会话阻塞。
- 成功开场后只存在一个温泉会话。
