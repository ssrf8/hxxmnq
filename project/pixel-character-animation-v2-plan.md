# 像素角色移动动画规划（V2 兼容 + 最终版可变长序列）

> 状态：当前运行时仍由灵梦 V2 r6、魔理沙 V2 r2 与其余角色旧图集承担。2026-07-28 已完成七名角色“最终版”序列的 P0 透明化、拆帧、可变列图集、`90ms` GIF 与第二轮蒙版优化，统一状态为 `generated-pending-owner-review`；尚未登记或接入。后续实施以 §13 的逐角色可变帧数合同为准，旧 V2 固定 32 帧合同仅保留作兼容与回退记录。
> 范围：庭园地图的八名来访角色。不会改动 `presence_snapshot`、bridge、事件结算或地图点击契约。

## 1. 目标

把当前「静止图 + 四帧循环 + 横向小幅往返」升级为有明显节奏和方向感的本地表现动画。角色的到场、区域和静止朝向仍只读 `presence_snapshot`；巡游、待机、转向和帧推进均为 UI 的临时派生状态，不能写入 `stat_data`。

旧 V2 的素材生产不再以“一次生成完整 32 帧图集”为交付路径。生图模型可用于建立四方向站立基准和少量关键姿势，但帧间运动、图集排版与像素级对齐由 Aseprite 完成；每完成一个动作组就验证基线和循环，再进入下一组。

2026-07-28 起，七名角色已有所有者整理并按播放顺序编号的“最终版”序列。对这些角色不再反向套用固定 32 帧生产合同，也不擅自删帧、补帧或重排；先按 §13 把原始四方向合帧转换成透明、可描述、可验收的逐角色图集。原有 V2 图集和旧 `turnaround + walk-cycle` 在新序列通过实机验收前继续作为回退。

## 2. 旧 V2 生产策略与失败边界

此前候选暴露出整图生图不适合作为动画终稿来源：向上帧未连续排满、向下动作跳变、帧位偏离 `9 × 4` 合同，左右循环也缺少可验证的接地—经过—高点节奏。模型擅长画出相近的姿势，却不可靠地维护精确的帧号、位置和运动连续性。

因此采用以下分工：

1. **生图阶段**：只生成四方向的站立基准图，并按需生成少量关键姿势参考；不要求其输出可直接裁切的整张图集。
2. **Aseprite 阶段**：以对应方向的站姿为母版，在同一画布、同一脚底基线下，用 `pixel_mcp` 分组制作待机、水平和垂直循环帧；Aseprite 项目文件是可编辑母档。
3. **逐组验收阶段**：先播放、叠帧和检查一个完整动作组；通过后才锁定该组并制作下一组。未通过的组只返修该组，不污染已确认帧。
4. **图集阶段**：所有组验收完成后，严格按第 4 节的 `9 × 4` 槽位导出透明 PNG；导出脚本或人工检查必须拒绝错位、漏帧和非透明空槽。

这条路线优先保证可控性：生成图提供角色设计与姿势灵感，Aseprite 负责动画师应负责的节奏、落点和报数。

## 3. 旧 V2 兼容素材合同（32 张）

所有帧使用透明 PNG、相同画布尺寸、相同脚底基线和相同像素密度；不可在不同方向偷偷改变角色缩放或地面落点。

| 动作 | 帧数 | 帧名 | 用途 |
|---|---:|---|---|
| 待机 | 4 | `idle-00` 至 `idle-03` | `idle-00` 为正常站立图；其余 3 张是轻微呼吸、眨眼或衣饰摆动。 |
| 向左 | 9 | `left-00` 至 `left-08` | `left-00` 为向左站定/起步姿势，`01`–`08` 为完整八步循环。 |
| 向右 | 9 | `right-00` 至 `right-08` | `right-00` 为向右站定/起步姿势，`01`–`08` 为完整八步循环。 |
| 向上 | 5 | `up-00` 至 `up-04` | `up-00` 为背向站定/起步姿势，`01`–`04` 为四步循环。 |
| 向下 | 5 | `down-00` 至 `down-04` | `down-00` 为面向站定/起步姿势，`01`–`04` 为四步循环。 |

合计 `4 + 9 + 9 + 5 + 5 = 32` 张。方向动作的 `00` 不与待机图共用：它承担该方向的站定、起步和收步，因此即使正面待机与向下站姿很接近，也应分别绘制。

> 本节至 §12 描述已经接入或留档的 V2 兼容资产，不再约束 `最终版/001.png` 起的可变长原始序列。新序列的事实表、输出合同和实施顺序统一见 §13。

### 3.1 动作组的关键帧节奏

- **水平 `01`–`08`**：以两步循环组织为 `左接地 → 下沉/经过 → 高点 → 右接地 → 下沉/经过 → 高点 → 回收 → 预备接地`。至少在 `01`、`04` 出现清晰且交替的接地帧，在 `03`、`06` 出现高点；`08 → 01` 的脚、躯干高度与摆动方向必须自然衔接。
- **垂直 `01`–`04`**：用较小振幅的四帧循环表现前后行走：`接地 → 经过 → 对脚接地 → 回收`。轮廓和脚底不应在单帧间突然抬升或下沉。
- **待机 `idle-01`–`03`**：只允许眨眼、呼吸、衣饰或发梢的微小变化；脚底线、角色高度、身体碰撞视觉中心固定不动。
- **方向 `00`**：必须能独立停留，且能同时衔接 `00 → 01` 与走动收步 → `00`；它不是被随手复制的占位图。

### 3.2 横向 8 帧步态基线（强制）

所有后续角色的水平行走均按归档指导 `project/animation-guides/8-frame-walk-cycle-guide.docx` 与配图 `8-frame-walk-cycle-guide.png` 制作、检查和验收。循环固定为：`F1 接触 A → F2 承重 A → F3 通过 A → F4 抬升 A → F5 接触 B → F6 承重 B → F7 通过 B → F8 抬升 B → F1`。

- 承重帧是全循环最低点，抬升帧是最高点；角色高度约 `150px` 时，身体总起伏取 `6px` 左右，头部起伏更小。
- 前后脚最大距离约为角色可见高度的 `18%–25%`；接触到蹬地期间，支撑脚的水平坐标不得滑动。通过帧双脚接近但不得并拢成站立姿。
- 手臂与腿反向摆动；手持物摆幅小于空闲手；披风、翅膀和挂件比身体变化延后一帧，且只作次级运动。
- 水平循环默认每帧 `130ms`（约 `7.7 FPS`）；后续可在 `120–140ms` 内按角色气质调整。琪露诺已按所有者验收意见从 `100ms` 下调到 `130ms`；必须检查 `F8 → F1` 无缩放、闪烁或跳脚。
- 角色的非对称设计默认不得镜像。**琪露诺例外：所有者已验收同一左行循环的水平翻向右行，允许复用同一套八帧并翻向。**

### 3.3 前视 / 后视指导的 V2 四帧适配（强制）

归档指导 `project/animation-guides/front-back-8-frame-walk-cycle-guide.txt` 与配图 `front-back-8-frame-walk-cycle-guide.png` 是前后行走的关键姿势与 L/R 语义来源；**当前 V2 交付规格仍保持 §3 的向上/向下各 5 格（`00 + 4` 循环），不扩张为 8 帧。**

- 对应 8 帧参考的 V2 取样固定为 `F1 左脚接触 → F3 右脚通过 → F5 右脚接触 → F7 左脚通过 → F1`；方向 `00` 仍由独立站定/起步姿承担，不能把参考帧直接拼成 8 格交付。
- 保留指导中的自身 L/R 映射：前视左脚在画面右、右脚在画面左；后视左脚在画面左、右脚在画面右。前视前脚向下、后视前脚向上；道具、冰翼、披风和头发的身份侧别不得翻转。
- 取样后仍须保持接触脚基线、头部横向漂移 ≤ `1px`、无缩放；次级物件只作约 `1px` 的延迟变化。V2 垂直循环按 §5 的默认 `130ms`（允许 `120–140ms`）和 `04 → 01` 边界验收。
- 如需把任何角色升级为完整前后 8 帧，必须先由所有者明确授权新的图集合同与运行时裁帧表；不得暗中把旧 `9×4` 规格扩成 10×4 或其它尺寸。

## 5. 播放规则

1. **到场或抵达**：使用该方向 `00` 帧 120–180ms，再进入对应走动循环。
2. **水平移动**：播放 `01`–`08`，默认每帧 `130ms`（可在 `120–140ms` 调整）；循环边界 `08 → 01` 必须无跳脚。
3. **垂直移动**：播放 `01`–`04`，默认每帧 `130ms`（可在 `120–140ms` 调整）；循环边界 `04 → 01` 必须无跳脚。
4. **停止**：完成当前短步后落到该方向 `00`，随后在 450–1100ms 内开始待机循环。
5. **待机**：播放 `idle-00 → 01 → 02 → 03 → 00`，每帧 350–600ms；不做缩放呼吸或 CSS 平滑位移，以免像素边缘发糊。
6. **转向**：先展示新方向 `00`，至少一个短帧后才开始移动，避免瞬间镜像翻转。
7. **减少动态效果**：固定为 `idle-00`，不位移、不切帧，保留当前无动画降级语义。

## 6. 运行时改造边界

- 将 `SpriteActor` 从 `idle | walk` 扩展为 `idle | turn | travel | settle`，并由一个 clip 描述表解析上述图集；不得再假定移动图是固定 `4×4`。
- `GardenMap` 仅为到场角色生成限制在所属区域锚点附近的小型二维路径。每段路径根据实际位移选择 `left/right/up/down`，不再只改 `offsetX`。
- 角色配置保留个性化的速度、停顿和轨迹：步行角色走短折线；魔理沙走低空弧线；琪露诺和米斯蒂娅以较小的纵向漂移巡游。它们共用 32 帧合同，不需要各自另造一套运行时协议。
- `presence_snapshot.character_views.facing` 是角色静止时的权威朝向；本地巡游期间可临时按路径朝向显示，停止后恢复该权威朝向。
- 命中范围、选中光晕、气泡菜单锚点继续跟随角色实际绘制位置；角色不在场时停止推进动画。
- 图集加载失败时回退到既有 turnaround 静态图；不会让角色消失或退回几何圆点。

## 7. 素材验收清单

- `9 × 4` 的全部 32 个命名槽位准确对应第 4 节；第 0 行的向上 5 帧连续位于第 5–9 列，不得夹入空白或其他帧。第 1 行仅第 1–5 列为向下帧，余下空槽必须完全透明。
- 32 格齐全、无色键背景、无半透明白边；不得依赖视觉上“差不多”的相似姿势替代缺失帧。
- 所有站立、待机、移动帧的脚底接触线与角色高度逐像素一致；以基准线叠帧检查，不接受凭肉眼估计。
- 水平组必须能辨认出交替接地、经过和高点；左右动作的 1、4、8 帧在视觉重量上平衡。
- 左右不可简单镜像（服饰、道具、发型和持物方向按角色设定绘制）；仅当所有者对某角色明确批准时，才可记录为翻向复用例外。
- 水平 8 步和垂直 4 步均能无缝循环；须在 Aseprite 中至少连续播放 3 个循环检查 `08 → 01`、`04 → 01`，并检查 `00 → 01` 与走动停止到 `00` 不突跳。
- 待机三张增量帧足以看见变化，但不改变脚底位置、角色体积或碰撞视觉中心。
- 单格尺寸、像素比例和角色占位与当前地图一致；导入前以同一底图叠放校验。

## 8. 试点实施顺序

1. 选定一名角色，生成或确认四方向站立基准图；锁定画布尺寸、缩放、脚底基线与视觉中心，建立可保存的 Aseprite 母档。
2. 先完成并验收 `idle` 组，再完成一个水平组（建议 `right`）；通过叠帧与三循环播放检查后，复制结构制作反向动作，但按角色设定重绘非对称服饰、道具和发型。
3. 逐组完成剩余水平和两个垂直组；每组完成即进行基线、关键帧节奏、循环边界和 `00` 起停衔接检查。任何失败只回退当前组。
4. 全部 32 帧合格后，按第 4 节组装图集并复核槽位；为该角色增加 V2 清单记录，同时保留旧 `turnaround + walk-cycle` 作为全局回退，其余七人不受影响。
5. 实现 clip 描述表、二维短路径和状态机，但仅对试点角色启用；完成类型检查、动画状态/裁帧/回退定向测试、现有 UI 测试和构建。
6. 实机验收：普通巡游、四方向、快速切换在场区域、悬停/选中锚点、后台恢复、320px 宽度和 reduced motion。
7. 试点通过后，再按相同生产与验收门槛批量接入另外七名角色；不以试点成功为由直接替换所有角色。

## 10. 强制 GIF 验收门（所有角色、所有动作组）

生成或重绘任何动画素材后，**不得直接进入下一方向、下一动作组或运行时接入**。必须先基于实际将要使用的透明图集导出 GIF 演示，并由所有者明确判定“通过”后，才允许锁定当前组并继续。

1. **导出时机**：每完成 `idle`、`left`、`right`、`up` 或 `down` 任一动作组即导出一次；若为整张图集首版，则先导出覆盖五组的总览 GIF。
2. **真实来源**：GIF 必须从待交付 PNG / Aseprite 母档裁切生成，禁止用提示图、单独预览图、色键图或手工拼出的替代帧冒充验收结果。
3. **播放规则**：idle 至少包含一次完整的 `00 → 01 → 02 → 03 → 00`；左右至少连续播放两个 `01 → 08 → 01` 循环；上下至少连续播放两个 `01 → 04 → 01` 循环；演示默认每帧 `160ms`，除非本轮另有书面裁定。
4. **验收内容**：检查角色可见高度、脚底最低点、头部水平中心、方向切换、接地—经过—高点节奏、循环边界、眨眼/呼吸过渡、透明边缘及空槽。不得只凭静态图集截图判定通过。
5. **失败处理**：发现任意缩放跳变、横向跳动、脚底漂移、帧序错误、动作不连续或视觉不规范时，只返修当前动作组；重导 GIF 并再次验收，未通过前不得污染已锁定的组。
6. **归档要求**：保留最终通过的 GIF、透明 PNG 与可编辑 `.aseprite` 母档；文件名需包含角色、图集版本和 `demo`，例如 `reimu-animation-v2-r6-demo.gif`。

盘点事实：

- 七个目录合计 151 张 PNG，编号全部连续、无缺号，单张均为 `640×640 RGBA`。
- 每张 PNG 是同一时间点的四方向 `2×2` 合帧：左上 `front`、右上 `back`、左下 `left`、右下 `right`。`001 → 002 → … → N` 是该角色唯一可信的原始播放顺序；四个方向必须使用相同序号同步取帧。
- 文件虽为 RGBA，但当前 151 张的 alpha 全部为 255，即都是不透明原图。灰白、黑色和绿色背景还含轻微色差、纹理或分隔线，不能用“某个精确 RGB 等于透明”的简单规则直接上线。
- “最终版”表示角色造型、动作内容和先后顺序以该目录为准，不等于已经完成运行时验收。原目录只读保留；透明化、裁切、图集和预览均输出到新版本文件，不覆盖 `001.png`–`NNN.png`。

### 13.2 新的运行时素材合同

新合同以角色自己的 `frameCount=N` 为准，不再要求所有角色拥有同样帧数：

```text
源输入：NNN.png = 640×640 四方向合帧
输出图集：N 列 × 4 行透明 PNG
row 0: front-001 ... front-N
row 1: back-001  ... back-N
row 2: left-001  ... left-N
row 3: right-001 ... right-N
```

- 每个输出单元格统一为 `209×209`，方向行顺序保持 `front/back/left/right`，以便沿用当前 `facingRow` 语义；列数由角色自己的 `frameCount` 决定。
- 原序列全部保留，不把 17/19/20/24/25 帧裁成 4、8 或 32 帧，也不复制帧凑统一长度。若后续确需动作分段，只能在描述表里用 `loopStart/loopEnd/idleFrame` 引用原序号，不能改写源顺序。
- 背景移除使用“从画布边界连通的背景分割 + 角色保护遮罩 + 边缘复核”，按角色分别设容差；不得只按单色键全图替换，以免删掉琪露诺黑色轮廓、灵梦绿色附近像素或灰白服饰高光。
- 每帧拆出四象限后，按透明主体包围盒统一缩放、脚底基线与水平视觉中心；同一角色的缩放参数必须锁定，不能逐帧自动放大到满格。所有缩放继续使用最近邻。
- 每名角色登记独立描述：`layout: variable-sequence-v1`、`columns`、`rows: 4`、`frameCount`、`rowOrder`、`frameDurationMs`、`idleFrame`、`loopStart`、`loopEnd`、基线、视觉中心和回退文件。运行时不得再把所有动画图集硬编码成 `9×4`。
- 在没有证据证明序列含独立待机段之前，停止时固定显示 `001`，移动时播放 `001 → N`；`prefers-reduced-motion` 同样固定 `001`。若 GIF 验收发现 `N → 001` 不能闭环，先在描述表收窄循环区间，不擅自重排或补画。
