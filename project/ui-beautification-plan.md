# 前端美化优化方案（UI Beautification Plan）

> 2026-07-26 起草，同日定稿艺术方向。基线：R48 维护源（`codex/backup-20260725-m2-plan` 分支）。
> 本方案只覆盖视觉与体验层，不改动任何契约行为：状态所有权、事件结算、bridge 事务边界、投影规则一律不动。
> 依据 `sillytavern-embedded-ui` skill 原则起草：先结构与状态、后色彩与装饰；离线通过 ≠ 实机通过，最终验收交给 `sillytavern-runtime-debug`。

## 1. 现状审计

### 1.1 已经做对的（保持，不要在美化中破坏）

| 项 | 位置 |
|---|---|
| 全部类名/ID 以 `gg-` 命名空间隔离 | `src/ui/styles.css`、`src/ui/index.html` |
| 44px 触控目标、`:focus-visible` 可见焦点 | `styles.css:20`、`styles.css:24` |
| `prefers-reduced-motion` 全局豁免动画 | `styles.css:420-422` |
| 窄屏（700px / 420px / 380px）与矮屏（720px / 560px）断点 | `styles.css:366-418` |
| `dvh`、`clamp()`、`minmax(0, …)`、`overflow-wrap: anywhere` 的弹性布局 | 全文 |
| 原生 `<dialog>`、语义化按钮/标题、`aria-live` 状态行 | `index.html:206`、`styles.css:260-283` |
| 模型输出全部走 `textContent`，无 `innerHTML` 注入 | `shop-view.ts`、`inventory-view.ts`、`app.ts` |
| 仅 2 处受控内联样式（目标菜单锚点 CSS 变量） | `app.ts:545-546` |
| 战斗弹窗样式独立命名空间，受弹幕优化协议约束 | `styles.css` `.gg-battle-*` |

结论：结构与状态层是健康的。美化工作可以直接进入视觉层，不需要先做架构性重构。

### 1.2 主要美化短板

1. **Token 层太薄，硬编码颜色散落。** `:root` 只有 11 个变量（`styles.css:1-14`），但全文散落约 30+ 个字面色值：输入框底 `#11161a`（4 处）、金边 `#d6b577`（4 处）、用户消息底 `#303c42`（2 处）、焦点色 `#f3c86c`、GAL 输入底 `#101417`、战斗底 `#161a24` 等。
2. **缺少间距/字号/阴影梯度。** padding、gap、font-size、box-shadow 逐处手写（`.7rem`/`.75rem`/`.8rem`/`.9rem` 混用），视觉节奏不统一。
3. **头部按钮区拥挤且无图标。** `gg-header` 里 5 个文字按钮（`index.html:57-61`）+ 状态胶囊挤在一行；`src/assets/ui/ui-icons-sheet-v1.png` 图标表已存在但未接入。
4. **庭园地图 canvas 标注是素圆点＋裸文字。** `garden-map.ts:186-200` 区域标记无衬底，文字直接压草地背景；天气/时段叠加素材 `world/overlays/weather-time-overlays-v1.png` 完全未用。
5. **GAL 场景背景是纯 CSS 渐变。** `gg-portrait-stage` 只有 4 组渐变（`styles.css:132-144`）；近景「立绘」实际是地图用像素 turnaround 直接放大（`character-sprite-registry.ts`），演出感弱；对话框无圆角、说话人无名牌。
6. **商店/背包/开放庭园/设置共用 `gg-settings` 白板样式**，由 TS 生成朴素 h2+p+button 流；无价格徽章、禁用理由样式、空状态设计。
7. **状态反馈单一。** 只有底部一行 `gg-live-status`；成功/警告/错误缺层级。
8. **微交互几乎为零。** 仅按钮 hover 变边框色。
9. **季节/时段主题未利用。** 头部已展示「春·第1日·清晨」与天气（本地派生），但配色恒定。

## 2. 艺术方向定稿：像素世界 × 东方二次元细腻演出（双层风格架构）

**一句话定位：玩家在「像素的幻想乡」里生活，在「细腻二次元的演出」里与角色相遇。**

参照物：HD-2D 式分层（像素资产 + 高品质光影包装）、东方官作符卡宣言的仪式感、二次创作 GAL 的立绘演出传统。

### 2.1 双层划分

| 层 | 风格 | 覆盖内容 | 渲染规则 |
|---|---|---|---|
| **世界层（玩法现场）** | 像素风，严格网格 | 庭园地图、行走小人、设施状态图、温室形态图、弹幕战、天气叠加 | `image-rendering: pixelated`；只允许整数倍/等比缩放；不加模糊、不加平滑光效 |
| **演出层（叙事与 chrome）** | 东方二次元细腻风 | 开场页主视觉、GAL 立绘与场景背景、对话框/弹窗/卡片的边饰、图标点缀、季节氛围 | 平滑渲染；柔和光影；线条干净；禁止对细腻素材做 pixelated |

**衔接规则（防止两层打架）：**

1. 两种分辨率语言不在同一图层内混合；像素素材出现在演出层时必须装进「取景框」——细腻风金色双线框 + 暗色衬底包裹像素内容（例：设施页大图、战斗画布）。
2. 全应用统一一套「符卡边框语言」（见 2.3），像素区和细腻区共用同一边框，视觉上由边框完成缝合。
3. 像素层的动效是帧动画/位移；演出层的动效是淡入、辉光、视差，两者不互换。

### 2.2 色彩体系（东方语汇 → token）

在阶段 A 的 token 层上落成以下语义色，全部取自东方经典意象：

| Token | 意象 | 用途 |
|---|---|---|
| `--gg-accent`（金 #d7a449 系） | 灯笼金 / 御币纸垂 | 强调、边框、eyebrow、选中态 |
| `--gg-accent-2`（朱 #9f3e46 系） | 鸟居朱红 / 灵梦红 | 主行动按钮、tab 指示 |
| `--gg-mystic`（新增，紫 #6c5c82 系） | 结界紫 / 隙间 | 异变相关 UI、待调查标记、神秘态 |
| `--gg-nature`（新增，绿 #7a9a6d 系） | 幻想乡草木 | 庭园/资源正向反馈、成功态 |
| `--gg-ice`（新增，青 #7ec8ff 系） | 琪露诺冰 / 月光 | 信息态、温泉/夜间点缀 |
| 底色三件套（bg/panel/panel-2） | 夜色木质 | 保持现暗色，微调偏暖 |

规则：主界面同屏最多「暗底 + 金 + 一个场景强调色」；朱红只给可点击的主行动；对比度一律 ≥4.5:1 复核。

### 2.3 纹样与母题（细腻感的主要来源，零位图成本优先）

按实现成本从低到高分三档，A/B 档全部用 CSS/内嵌 SVG（不增卡体积）：

- **A 档（纯 CSS）**：
  - **符卡宣言框**：演出层通用容器——外 1px 金线 + 内 1px 半透明金线的双线框、四角小方块角饰（`::before/::after` + `background: linear-gradient` 拼角）；应用于 GAL 对话框、目标菜单、历史弹窗、设施卡。
  - **纸垂分隔线**：标题下方用小三角波形渐变代替素横线。
  - **辉光强调**：选中/激活元素外圈 1px 金色 + 微弱 `box-shadow` 光晕（代替大面积 glow）。
- **B 档（内嵌 SVG data URI，每个 <1KB）**：
  - 阴阳玉小图标（资源/金币）、五芒星（魔理沙相关/装饰弹点）、结界几何淡纹（面板背景 4% 透明度平铺）、卷云纹页眉饰。
- **C 档（位图，走素材生产线，见 §7）**：
  - 开场主视觉、GAL 场景背景、角色细腻立绘差分。

### 2.4 排印

- 标题层字体栈前置衬线：`"Source Han Serif SC", "Noto Serif SC", "Songti SC", serif`——系统有则获得和风衬线标题，无则安静回退；正文维持现 sans 栈。**不打包任何字体文件。**
- 标题追加 `letter-spacing: .06em`，eyebrow 保持 `.12em`；数字全部 `tabular-nums`。
- GAL 正文行高 1.72 保持；字号引入 `--gg-fs` 梯度后微调层级（说话人名 > 正文 > 进度提示）。

### 2.5 各视图的双层落位

| 视图 | 世界层成分 | 演出层成分 |
|---|---|---|
| 开场页 | 无 | C 档主视觉背景（暗化 40% 垫底）+ 符卡框表单，「在穿过结界之前」标题用衬线栈 |
| 庭院地图 | 像素地图/小人/天气叠加（原样） | 地图外框、目标菜单、待办卡用符卡框；canvas 内标签加半透明圆角衬底（画在 canvas 里，风格中性不破坏像素感） |
| GAL 场景 | （过渡期）像素立绘装进取景框 | 场景背景（C 档，按区域）、细腻立绘差分（C 档，终态）、符卡宣言式对话框、名牌、选项菱形标记 |
| 设施页 | 像素设施大图 | 取景框 + 符卡风信息卡、纸垂分隔的费用清单 |
| 商店/背包 | 像素图标（ui 雪碧图） | 「神社摊位」卡片：纸札形价签、阴阳玉金币图标 |
| 弹幕战 | 全部（协议管辖，不动） | 仅允许消费全局 token |
| 设置/诊断 | 无 | 最低装饰，保持工具感 |

### 2.6 立绘策略（GAL 细腻化的关键路径）

现状：GAL 近景复用地图像素 turnaround 放大，这是「细腻二次元」目标下最大的观感缺口。分两步走，避免被素材产能卡死：

- **过渡态（不需要新素材，随阶段 C 落地）**：像素立绘装进「取景框」——缩小占比（约 50% 高度）、置于符卡框内、背后垫区域渐变 + 结界淡纹，明示「这是像素小人的特写」而非假装高清立绘；反应色调仍由 `data-reaction` 驱动。
- **终态（依赖素材生产线 §7）**：8 位固定角色的细腻二次元立绘，半身像、闭嘴中性/微笑默认（沿用像素素材同一表情纪律），差分对应现有 reaction 白名单（`neutral / smile / annoyed / serious`，以实际注册表白名单为准）；由本地素材注册表解析，LLM 仍只能选白名单标签（契约不变）。素材就位后 `#gg-portrait` 切换为平滑渲染 + 底部渐隐，像素取景框方案保留为缺素材角色的回退。

### 2.7 反面清单（这个方向上明确不做的事）

- 不做全屏 bloom/大面积辉光——东方感来自「符卡的仪式感」，不是滤镜堆叠。
- 不给像素素材加抗锯齿、阴影羽化或非整数缩放。
- 不做 Live2D / 骨骼动画立绘。
- 不用 AI 生成素材未经统一审阅直接入卡（沿用 `asset-manifest.json` 的 `unified-review-after-batch-generation` 流程）。
- 不因美化把任何界面信息密度打散（操作面保持紧凑，spectacle 只留给开场和 GAL）。

## 3. 设计原则（工程侧）

1. **只加视觉层，不碰数据层。** 季节/时段/天气/反应主题一律由本地 `stat_data` 派生为 `data-*` 属性挂在 `.gg-app`/对应容器上，CSS 变量切换；不新增 MVU 字段，不让 LLM 影响样式。
2. **一切动效走 token + reduced-motion 豁免。** 新动画统一 `--gg-dur-1/2`，沿用 `styles.css:420` 全局豁免。
3. **战斗命名空间不越界。** `.gg-battle-*`/`.gg-dungeon-*` 归 `project/bullet-hell-minigame-optimization-protocol.md` 阶段 B 管辖；本方案不改这些选择器，只允许它们消费新 token。
4. **不引入框架、webfont、外部资源、`backdrop-filter`。**
5. **体积纪律。** 检查点 dry-run 已约 30MB；新增位图素材有预算上限（见 §7.3），CSS/SVG 方案永远优先。
6. **对比度门槛 4.5:1**，所有新配色落地前复核（现 `--gg-muted` 压 panel 约 5.5:1 达标）。

## 4. 优化项清单（按阶段）

### 阶段 A：Design Token 重构（纯整理，预期零视觉变化）

- `:root` 扩展：
  - 颜色：`--gg-input-bg`、`--gg-gold`、`--gg-focus`、`--gg-user-msg`、`--gg-mystic`、`--gg-nature`、`--gg-ice`、`--gg-overlay`、`--gg-shadow-1/2`（§2.2 语义表）；
  - 尺度：`--gg-space-1…5`、`--gg-radius-s`/`--gg-radius`、`--gg-fs-s/m/l`、`--gg-dur-1/2`；
- 全文替换硬编码值为 token；`.gg-battle-*` 区块字面值本阶段不动。
- 数字启用 `tabular-nums`；标题层切衬线栈（§2.4）。
- 验证：逐视图截图与改前比对，无意图外差异（衬线标题是本阶段唯一允许的可见变化）。

### 阶段 B：全局 chrome 统一（符卡边框语言落地）

- **符卡框组件类** `gg-spell-frame`（A 档纹样）：双线金框 + 角饰，替换目标菜单、历史弹窗、设施卡、待办区现各自为政的金边写法。
- **头部改造**：5 个入口接入 `ui-icons-sheet-v1.png`（图标 + 文字，窄屏只留图标 + `aria-label`）；状态胶囊加阴阳玉/时段小图标（B 档 SVG）；资源变化数字轻微脉冲（reduced-motion 豁免）。
- **按钮三档**：主行动（朱红）、次级（面板底）、危险/不可逆；统一 hover/active 过渡。
- **卡片语言统一**：`gg-shop-item`、`gg-dungeon-entry`、`gg-pending-task`、`gg-session-history-entry`、inspector 收敛为一套卡片样式。
- **标签页**：选中态改「底部 2px 金色指示条 + 文字提色」，保留 `aria-selected` 驱动。
- **面板底纹**：panel 背景叠 4% 透明度结界几何淡纹（B 档 SVG 平铺），远看是质感、近看不抢内容。

### 阶段 C：核心视图专项

- **庭园地图（garden-map.ts 绘制层）**：
  - 区域标记升级：图标底座 + 描边 + 半透明圆角衬底标签（canvas 内绘制，中性风格）；
  - 选中目标高亮环，与目标菜单联动；字号随 DPR/zoom 补偿；
  - 接入 `weather-time-overlays-v1.png` 天气/时段色调叠加（静态合成）。
- **GAL 场景（过渡态，不依赖新素材）**：
  - 对话框改符卡宣言框：`--gg-radius-s` 圆角、双线金框、左上角说话人名牌（底色随 `data-reaction` 微调）；
  - 像素立绘取景框方案（§2.6 过渡态）；
  - 正文整段淡入 ≤0.3s（不做逐字打字机，避免拖慢 24 段演出门槛）；
  - 建议回应改「对话选项」造型（左侧小菱形，hover 提亮）。
- **商店/背包/开放庭园**：神社摊位卡片、纸札价签（金币图标 + tabular 数字）、持有数角标、禁用理由样式、空状态（B 档图标 + 一句话）。
- **设施页**：像素大图取景框化，费用清单纸垂分隔、确认按钮升主行动样式。
- **状态反馈**：`gg-pending-tasks` 左侧色条（普通/紧急）；`gg-live-status` 支持 `data-tone="info|success|error"` 三色。

### 阶段 D：季节与时段氛围主题

- `app.ts` 单点派生 `dataset.season / daypart / weather`。
- CSS 按 `data-*` 切换少量 token：头部渐变端色、强调色微调（春樱粉金 / 夏青竹 / 秋枫橙 / 冬雪蓝）、GAL 渐变端色、地图外框色。
- 非目标：全屏粒子（樱吹雪/落雪）不做；如所有者要求，另立可关闭项。

### 阶段 E：微交互与收尾

- 视图切换 0.15s 淡入；`<dialog>` 开合缩放淡入（`@starting-style` + 回退）；目标菜单锚点侧缩放弹出。
- 全部动效验证 reduced-motion 下瞬时完成、无信息只存在于动画中。
- 收尾：全视图截图集（1100px / 700px / 380px、200% 缩放、reduced-motion）归档附录。

### 阶段 F：细腻素材接入（依赖 §7 生产线，可与 A–E 并行制备、最后接入）

- F1：GAL 细腻立绘差分接入（`#gg-portrait` 切平滑渲染 + 底部渐隐；像素取景框保留为回退）。
- F2：GAL 区域场景背景接入（`data-area` 驱动，无素材回退渐变）。
- F3：开场页主视觉接入。

## 5. 明确不做（工程边界）

- 不改 `.gg-battle-*`、`.gg-dungeon-*` 视觉（归弹幕协议阶段 B）。
- 不引入 webfont、外部 CSS/JS、`backdrop-filter`。
- 不做浅色主题（卡内壳保持自控暗色 `color-scheme: dark`）。
- 不新增 MVU 字段、不改 `*-rules.ts` 纯函数、不改事件/结算/bridge 逻辑。
- 不重排 `index.html` 语义结构（只允许装饰性 span/class 与 `data-*`）。
- §2.7 反面清单同为硬边界。

## 6. 实施与验收流程

每个阶段独立成一次提交，流程固定：

1. 修改维护源（`styles.css` 为主；B/C/D/F 涉及 `app.ts`/`garden-map.ts`/`*-view.ts` 类名与 `data-*` 注入、素材注册表）。
2. 离线门禁：`npm run check:ui` → `npm test`（当前 134/134）→ `npm run build:ui`；只有明确要求检查点时才运行 `npm run package:checkpoint:dry`／正式打包。
3. 截图证据：按 §4.E 矩阵截图，对比改前基线。
4. 更新本文档勾选状态。

**实机验收交接（sillytavern-runtime-debug）**：

| 类别 | 用例 |
|---|---|
| 渲染 | 新聊天开场页、进入庭院、Swipe/重生成/编辑后壳不重复挂载、切卡后样式完全清理（r14 契约） |
| 样式 | 实机 computed style 抽查（ST 可能改写静态 HTML 类名——动态 DOM 与静态模板都要验证）、暗色宿主下无穿透、金色文字对比度、像素素材无被平滑 |
| 布局 | 320px 宽、200% 缩放、矮屏 560px、移动端键盘弹出时 GAL 输入区可见 |
| 动效 | reduced-motion 开启后无残留；地图天气叠加不掉帧 |

## 7. 细腻素材生产线（阶段 F 供给）

### 7.1 清单与规格

| 素材 | 数量 | 规格建议 | 优先级 |
|---|---|---|---|
| 角色细腻立绘（半身，默认表情） | 8（固定角色全员） | 高约 1024px，透明底，闭嘴中性/微笑（沿用像素素材表情纪律） | F-P0 |
| 立绘反应差分 | 8 × 3（对应 reaction 白名单非默认项） | 同底同构图，仅表情/小幅姿态差分 | F-P1 |
| GAL 区域场景背景 | 6（庭院/温室/主屋/温泉/宴会广场/妖精花园） | 1280×720 级，时段变化由 CSS 色调完成，不出多时段版本 | F-P1 |
| 开场主视觉 | 1 | 1280×960 级，庭园远景 | F-P2 |

### 7.2 流程

- 沿用 `asset-manifest.json` 管理：新增 `portrait_*` / `scene_*` 条目，`style_reference` 单列细腻风参考（与像素 `style_reference` 分开，明确「仅构图与配色参考」）。
- 沿用 `review_mode: unified-review-after-batch-generation`：批量出图 → 所有者统一审阅 → `status: approved` 才接入注册表。
- 立绘接入点：`character-sprite-registry.ts` 旁新增独立的 portrait 注册表（不与地图 sprite 混表），按 `id + reaction` 解析，miss 时回退像素取景框。

### 7.3 体积预算（硬约束）

- 当前检查点约 30MB；细腻素材新增总预算 **≤6MB（压缩后）**。
- 立绘：无损转 WebP/有损高质量，单张目标 ≤120KB → 8×4 ≈ 3.8MB 上限。
- 背景：单张 ≤250KB → 6 张 ≈ 1.5MB。主视觉 ≤300KB。
- 超预算时裁剪顺序：先砍反应差分（只留默认表情）→ 再砍背景张数（保庭院/温室）→ 最后才考虑降分辨率。
