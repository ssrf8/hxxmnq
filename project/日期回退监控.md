## BUG-001 跨日清晨日期回退到第一天

| 项 | 内容 |
|---|---|
| 状态 | 🔴 已复现（临时副本复现测试命中） |
| 严重度 | 高（存档状态错乱，玩法进度感知倒退） |
| 现象 | 推进到下一天清晨时，`environment.day` 回到第一天（发送前快照值） |
| 复现测试 | `幻想乡模拟器-bugtest-tmp/tests/bug-repro.test.mjs` → `BUG1` / `BUG1b`（临时副本） |

### 根因

`src/ui/bridge.ts:502` 本地结算路径：

```ts
const safeCurrent = restoreLocalEventOwnership(ownershipBase, current, true);  // lockTime=true
```

`restoreLocalEventOwnership`（`src/ui/event-settlement.ts:886-894`）在 `lockTime=true` 时**无条件**执行：

```ts
next.environment.day = before.environment?.day ?? 1;
next.environment.time_period = before.environment?.time_period ?? '清晨';
```

- `before`（ownershipBase）是**发送前快照**；
- 模型在同一轮回复里通过 `<UpdateVariable>` 推进时间（day=2 清晨）时，该分支把 day 无条件抹回快照值；
- `enforceMonotonicTime` 只拒绝倒退、允许前进，但 `lockTime` 分支连前进也抹掉；
- 跨日剧情常伴随固定事件结算（任务/维修/每日安排），必然命中此路径。

### 修复方向（未合入，待确认）

- 方案 A：`persistLocalSettlement` 的 `lockTime` 改为 `false`；
- 方案 B：`lockTime` 语义改为"仅拒绝倒退、允许前进"（即直接依赖 `enforceMonotonicTime`，删除覆盖分支）。

### 监控要点

- [ ] 本地结算写盘后校验 `environment.day` 是否 ≥ 发送前快照
- [ ] 模型 `<UpdateVariable>` 推进时间的轮次，检查写盘前 `restoreLocalEventOwnership` 是否被调用
- [ ] 跨日清晨 + 固定事件结算组合路径回归

## BUG-002 GAL 界面"正在生成回应"假死

| 项 | 内容 |
|---|---|
| 状态 | 🔴 已复现（临时副本复现测试命中） |
| 严重度 | 中高（界面卡死，需手动刷新/停止） |
| 现象 | 多次长对话后，GAL 界面持续显示"对方正在回应……"，实际回复已落盘 |
| 复现测试 | `幻想乡模拟器-bugtest-tmp/tests/bug-repro.test.mjs` → `BUG2`（临时副本） |

### 根因

`src/ui/async-coordination.ts:19-29`：

```ts
if (typeof nativeButtonGenerating === 'boolean') return nativeButtonGenerating;  // 原生状态一票否决
return active && !transaction.assistantResponded;
```

- `nativeButtonGenerating` 读取酒馆原生状态：`body[data-generating=true]` 或 `#mes_stop` 的 computed style（`src/ui/bridge.ts:168-181`）；
- 只要原生状态残留为 true，即使 `assistantResponded=true`、事务已 `settled`，`readTransaction()` 仍判定 `hostGenerationActive=true`；
- `getTransactionState()`（`src/ui/bridge.ts:1081`）据此永远返回 `phase:'generating'` → UI 假死；
- 长对话后酒馆/Luker 的 `data-generating` 残留不清理即触发。

### 修复方向（未合入，待确认）

- 方案 A：`reconcileHostGenerationActivity` 增加守卫 —— `assistantResponded` 为 true 时原生状态不再优先；
- 方案 B：加超时兜底 —— 原生生成状态持续超过阈值且事务已 settled 时强制复位 `hostGenerationActive`。

### 监控要点

- [ ] `hostGenerationActive` 在 `GENERATION_ENDED` / `GENERATION_STOPPED` 之外的复位路径
- [ ] `body[data-generating]` 与 `#mes_stop` 在长对话后的残留情况
- [ ] 事务 `phase` 已 `settled` 但 UI 仍显示 generating 的时长统计
