# GAL 首轮输入与历史画廊轻量实施计划

日期：2026-08-11
状态：已完成

## 目标

1. 玩家在角色菜单点击“对话”后先进入 GAL 输入页，不再自动发送开场消息。
2. 未发送前显示目标角色的普通立绘、姓名、输入框、道具选择器和“结束聊天”。
3. 未发送便结束时直接返回庭院，不调用 LLM、不创建消息楼层、不修改 MVU。
4. 在“幻想乡案内”增加只读回想画廊，从当前聊天的真实楼层生成剧情回想和图片回想。

## 约束

- 只改变普通角色动作 `action_id=talk`；摸头、符卡对战、固定事件和设施行动保持现状。
- 首轮草稿只存在于 iframe 内存，不新增 schema、存档字段或数据库。
- 第一次发送仍写入 `GensokyoAction(action_id=talk)`，保证目标锁定、历史分组和刷新恢复；玩家可见文本只显示输入原文。
- 画廊只读，复用 `bridge.listMessages()`、`projectGalScene()` 和 `resolveGalPortraitSource()`。
- 画廊单独读取最近 1000 个真实楼层；玩家可按真实楼层号填写起止范围，并用滑杆在筛选后的剧情楼层间快速定位。bridge 其他调用仍保留默认 80 楼，不做分页、搜索、收藏、分类或独立解锁表。
- 图片按当前素材表解析。项目不会轻易替换素材池，因此第一版不保存历史图片字节或额外素材 key。

## 阶段 A：普通对话等待首次输入

1. 点击“对话”时设置一个本地首轮草稿状态并进入 GAL。
2. 渲染目标角色默认 `normal / neutral / default` 立绘和空输入框，不读取旧 assistant 楼层。
3. 第一次提交时用玩家原文构造带 `talk` 行动标记的模型输入，并把原文作为 `gensokyoUserVisibleText`。
4. 提交成功后清除草稿状态，后续多轮对话继续走现有流程。
5. 草稿状态点击“结束聊天”时只清 UI 并返回庭院。

## 阶段 B：只读回想画廊

1. 在“幻想乡案内”增加“回想画廊”入口。
2. 打开时读取最近真实楼层，把每个非空 assistant 楼层投影成一个剧情回想条目。
3. 用相邻的上一条 user 楼层提取玩家可见原文作为条目摘要。
4. 点击剧情条目后打开独立只读 GAL 播放器，可逐段查看姓名、正文和对应立绘／CG。
5. 从所有剧情片段解析图片地址并去重，生成图片回想网格；点击图片打开对应剧情与片段。
6. 画廊播放器不显示输入框、道具、建议回复、重新生成或停止按钮。
7. 起始／结束楼层只筛选 assistant 剧情条目；滑杆按时间顺序定位范围内的剧情，并可直接打开当前楼层。

## 验收条件

- 点击“对话”后没有新增 user／assistant 楼层，输入框立即获得焦点。
- 首轮输入只发送一次；历史中玩家可见文本与输入逐字一致。
- 首轮未发送直接结束不会调用 bridge 本地结算或 LLM。
- 摸头、固定事件、设施和符卡入口仍维持原行为。
- 画廊打开与浏览期间不产生任何消息或 MVU 写入。
- 历史剧情能够逐 beat 播放；有图片的 beat 能在图片网格打开。
- 空历史、纯旁白、缺失立绘和旧格式消息均安全降级。

## 实施结果

- 普通角色“对话”已改为本地首轮草稿：进入 GAL 后等待玩家输入，首次提交才创建真实消息事务。
- 草稿未发送时“结束聊天”直接返回庭院，不调用 bridge 结算、LLM 或 MVU。
- “幻想乡案内”已增加只读回想画廊，包含剧情回想列表、逐 beat GAL 播放器和去重图片网格。
- 回想数据直接读取当前聊天最近 1000 个真实楼层，并按玩家选择的楼层范围筛选；图片仍按当前素材注册表解析，未新增 schema、存档字段或独立数据库。
- 尚有活动 GAL 对话时会提示先结束聊天，不会为了进入画廊丢弃本地会话指针。
- 摸头、固定事件、设施行动与符卡入口未改变。

## 实机验收建议

1. 点击任意角色的“对话”，确认进入 GAL 后没有自动生成消息且输入框可用。
2. 不输入内容直接点击“结束聊天”，确认返回庭院且聊天楼层数、MVU 均不变。
3. 再次进入并发送首句，确认只生成一次 user／assistant 事务，玩家楼层只显示原始输入。
4. 打开“幻想乡案内 → 回想画廊”，确认剧情可逐段翻阅、图片可由网格打开，浏览期间不新增楼层。
