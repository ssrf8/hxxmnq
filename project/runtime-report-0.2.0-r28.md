## 问题证据

R27 聊天中出现了叙事与地图状态冲突：正文写“魔理沙骑扫帚离开了”，同一楼层持久化的 `presence_snapshot` 仍将 `marisa` 列为在场、位置为温室。因此下一轮模型仍可能把已离场角色当作现场角色，地图小人也不会离开。

## R28 处理方式

1. `withGardenNarrativeContract(message, state)` 在每次庭院请求中追加唯一事实来源：在场名单、每名角色的位置/动作/朝向，以及完整不在场名单。
2. 角色出入场或换区时，模型在正文末尾返回 `<GensokyoPresence>` 受控回执；普通正文不要求回执。
3. `parsePresenceUpdate` 对版本、角色 ID、区域、动作、朝向进行白名单校验；未知角色与非法朝向被丢弃。
4. `applyPresenceUpdate` 在真实 assistant 楼层完成后原子覆盖 `presence_snapshot`，并删除离场角色视图。
5. 受控本地结算和普通自由互动都接入相同同步链，避免只修一种互动路径。
