# 大型功能入口面板规划

> 目标：解决顶栏「符卡副本 / 灵梦小店 / 背包」入口在浏览器缩放下模糊、拥挤的问题。
> 范围：只调整入口层和临时面板，不修改商店、背包、副本的业务行为、状态所有权或结算事务。

## 1. 产品定义

将当前顶栏中的三个大型图片入口收拢为一个稳定、清晰的「幻想乡案内」按钮。点击后打开一个覆盖庭园上方的大型功能面板；面板内使用三张大尺寸主入口卡：

1. 符卡副本
2. 灵梦小店
3. 背包

「开放庭园」「全屏」「设置」仍是辅助功能，不与三项主要玩法争夺同一视觉层级。第一版将它们放在面板底部的次级操作栏；是否最终全部移出顶栏，以离线预览反馈为准。

这个面板是临时 UI 状态，不进入 `stat_data`、MVU、世界书或聊天楼层。关闭后仍停留在原庭园视图。

## 2. 现状判断

- 三张入口源图分别约为 `1243x1025`、`1286x660`、`1349x644`，素材分辨率足够。
- 当前源图被压入约 `116–170px` 的顶栏按钮，并强制使用 `image-rendering: pixelated`。
- 页面还会通过 `--gg-browser-zoom-compensation` 补偿浏览器缩放。高分辨率插画在多重非整数缩放与像素化采样下容易发糊或产生锯齿。
- 因此本轮不需要重新生成入口图；应让大面板使用更大的稳定 CSS 尺寸，并对这三张插画明确使用 `image-rendering: auto`。

## 3. 页面结构

推荐使用原生单例 `<dialog>`，与现有副本、历史记录弹窗保持一致，但建立独立命名空间：

```text
顶栏
├─ 庭园名称与状态
├─ 幻想乡案内（新入口）
└─ 可选保留：全屏

大型功能面板 gg-launcher-dialog
├─ 页眉
│  ├─ 标题：幻想乡案内
│  ├─ 当前日期 / 天气 / 资源摘要
│  └─ 关闭按钮
├─ 主要入口网格
│  ├─ 符卡副本大按钮
│  ├─ 灵梦小店大按钮
│  └─ 背包大按钮
└─ 次级操作栏
   ├─ 开放庭园
   ├─ 全屏
   └─ 设置与恢复
```

不在面板中复制商店、背包或副本内容。点击大按钮后关闭入口面板，再调用现有入口函数：

- 小店：`setView('shop')` + `renderShop()`
- 背包：`setView('inventory')` + `renderInventory()`
- 副本：`openDungeonMenu()`
- 开放庭园：`setView('opportunities')` + `renderOpportunities()`

这样入口只换壳，现有业务路径不分叉。

## 4. 尺寸与布局

### 桌面端（建议基准宽度 >= 900px）

- 面板宽度：`min(1120px, calc(100% - 32px))`
- 面板最大高度：`min(820px, calc(100dvh - 32px))`
- 三张主入口卡：三列布局，最小高度 `220px`
- 图片安全区：高度 `150–190px`，`object-fit: contain`
- 整张卡片都是一个真实 `<button>`，而不是图片上再叠一个小按钮

### 中等宽度（560–899px）

- 两列网格
- 符卡副本可占满首行，商店与背包并列
- 卡片最小高度 `180px`

### 窄屏（<= 559px）

- 单列布局
- 面板贴近视口但保留 `8–12px` 安全边距
- 卡片高度 `132–156px`
- 面板主体内部滚动，页眉与关闭按钮保持可见
- 不使用固定 `100vh`，采用 `dvh` 与最大高度约束

## 5. 视觉方案

- 面板外壳沿用现有符卡双线框，但减少嵌套边框与大面积模糊。
- 背景采用深夜木色 + 低透明结界纹，入口图自身作为主要视觉，不再叠多层装饰。
- 三项入口分别使用既有主题：
  - 符卡副本：结界紫 / 樱粉
  - 灵梦小店：鸟居朱红 / 纸色
  - 背包：魔理沙金 / 深棕
- 图片设置 `image-rendering: auto`，禁止继承地图像素素材的 `pixelated` 规则。
- hover 只做轻微上浮、边缘增亮；active 做 1–2px 下压；`prefers-reduced-motion` 下取消位移动画。
- 禁用态必须显示可见原因文字，不能只依赖透明度或 `title`。

## 6. 交互与无障碍

- 打开后焦点进入面板标题后的第一个可用入口。
- `Escape`、关闭按钮和安全的背景点击都可关闭；关闭后焦点返回「幻想乡案内」。
- 原生 `<dialog>` 负责模态语义；标题通过 `aria-labelledby` 关联。
- 每个大按钮保留清晰的可访问名称，即使图片加载失败也能使用。
- 图片 `alt=""`，按钮内另有真实标题和状态文本，避免重复朗读。
- 大按钮触控面积显著超过 44px；键盘焦点环不被裁切。
- 面板打开状态仅存于 DOM，不持久化。

## 7. 实现边界

预计修改：

- `src/ui/index.html`：增加案内入口与 `gg-launcher-dialog` 结构。
- `src/ui/app.ts`：集中封装现有入口动作，绑定打开、关闭、转场和焦点返回。
- `src/ui/styles.css`：新增 `.gg-launcher-*` 样式与三个响应式档位；移除或停用旧顶栏三图缩放规则。
- `tests/ui-contract.test.mjs`：增加结构、入口唯一性、图片渲染策略和业务函数未分叉的契约断言。

明确不修改：

- 商店购买、背包使用、副本解锁与战斗结算逻辑。
- `bridge.ts`、MVU schema、世界书、事件登记表。
- `.gg-battle-*` 的战斗画布几何和输入协议。
- 三张现有入口图片源文件。

## 8. 施工顺序

1. 抽出 `openShop / openInventory / openOpportunities` 等统一入口函数，保证新旧入口临时并存时不会出现两套行为。
2. 加入单例案内 dialog 和三张大入口卡，先以现有素材完成桌面布局。
3. 将顶栏三个图片按钮替换为单一案内入口；保留全屏作为紧急可达操作。
4. 完成两列与单列响应式布局、短视口内部滚动。
5. 补齐焦点进入、Escape、关闭后焦点返回与 reduced-motion。
6. 运行 `check:ui -> test -> build:ui`，刷新离线预览。
7. 离线检查 100% / 125% / 200% 页面缩放，以及 390px / 320px 宽度。
8. 最后交给真实 SillyTavern 检查类名改写、iframe 尺寸、重挂载和聊天切换。

## 9. 验收标准

- 顶栏不再展示三张被压缩的小入口图。
- 点击「幻想乡案内」只生成或打开一个面板，不重复挂载。
- 三张主入口图在 100% / 125% / 200% 浏览器缩放下保持清晰，无 `pixelated` 锯齿。
- 主入口按钮在桌面足够大，在 320px 下不横向溢出。
- 点击任一入口仍走现有业务路径，关闭面板不会修改正式状态。
- 键盘可完整完成打开、切换入口、进入功能和关闭返回。
- 控制台无新增 warning / error；类型检查、测试和构建全绿。

## 10. 第一版建议取舍

第一版先做「一个案内入口 + 三张玩法大卡 + 三个次级文字按钮」，不加入分页、可拖动面板、入口排序或持久化偏好。先把清晰度、层级和操作距离做对；那些看起来很聪明的小机关，通常只是换个地方增加维护费而已。
