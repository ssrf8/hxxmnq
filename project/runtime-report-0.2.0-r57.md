# 0.2.0-r57 确定性开场修复报告

## 问题

r56 在真实 SillyTavern 新聊天中会提交生成式继承序章并等待 assistant 回复，界面因此可能长期停在“祖父留下的故事仍在展开”。这违反既定的零生成初始化契约。

## 修复

- 默认开场确认只调用 `initializeOpening(draft, frozenChatId)`。
- 写入目标固定为没有 user 楼层的新聊天中的首个 assistant 楼层。
- 合并 `initial-state.json` 后使用 `Mvu.replaceMvuData` 幂等写入，并立即复读关键字段。
- 不创建 user 或 assistant 消息，不触发 `/trigger`，不调用 LLM。
- 生成式序章、等待回复和修复按钮不再进入默认 UI；桥接层保留旧标记解析，仅用于历史存档兼容。
- 第一次 LLM 调用推迟到玩家进入庭园后的第一次真实行动。

## 真实运行待验收

1. 导入 r57 并新建聊天。
2. 记录入场前楼层数，填写资料后点击“接过庭守钥 · 进入庭园”。
3. 确认没有生成提示、没有新增玩家楼层，楼层数保持不变并直接进入庭园。
4. 刷新后仍停留在庭园，玩家资料、庭园名和庭守钥状态保持。
5. 在庭园执行第一次真实行动，确认此时才出现第一次 LLM 请求。

r56 保留为历史产物但已被替代，不应继续用于验收。
